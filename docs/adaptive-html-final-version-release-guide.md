# adaptive-html-final 버전 릴리스 정합 가이드

> 목적: `adaptive-html-final`에서 승인 없는 버전 상승과 버전 표면 드리프트를 막기 위한 운영 가이드다. 버전업은 수정 1건 단위가 아니라 **릴리스 단위**로만 수행한다. 전체 파일 감사 증거는 [버전 표면 전체 파일 감사 기록](adaptive-html-final-version-surface-audit-20260613.md)을 함께 본다.

## 1. 절대 원칙

| 원칙 | 규칙 |
|---|---|
| 사용자 승인 필수 | `manifest.version` 변경은 사용자가 명시적으로 “버전 올려”, “릴리스 해”, “vX.Y.Z로 배포”라고 지시했을 때만 허용한다. |
| 기본은 현재 버전 유지 | CSS·examples·게이트·문서·`.skill` 재패키징만으로는 버전을 올리지 않는다. |
| 버전은 마지막 단계 | 코드/문서/examples/source snapshot/package/검증이 모두 끝난 뒤 마지막에 한 번만 올린다. |
| 개발 중 변경은 Unreleased | 승인 전 변경 기록은 `CHANGELOG.md`의 `## Unreleased` 또는 dev-plan에만 남긴다. |
| output은 정본 아님 | `output/`은 공개 데모/테스트 산출물이다. 버전업 시 자동 정합 대상이 아니며, 명시 승격한 경우만 수정한다. |
| 패키지는 항상 재생성 | 버전 표면·예제·검증기·문서가 바뀌면 `skills/adaptive-html-final.skill`을 재패키징하고 byte-match를 확인한다. |

## 2. 승인된 버전업 전제 조건

버전업을 진행하려면 아래 중 하나가 현재 작업에 존재해야 한다.

- 사용자 대화에서 명시 승인: `버전 올려`, `릴리스`, `vX.Y.Z로 배포`, `버전 bump 진행`
- 또는 저장소 파일: `dev-plan/release-approval-vX.Y.Z.md`

승인이 없으면 `manifest.version`·`SKILL.md > Version`·README badge·examples visible version을 변경하지 않는다.

## 3. 버전업 시 반드시 수정/확인할 파일 표면

아래 목록은 저장소 전체 버전 문자열 스캔과 현행 v5.10.x 릴리스 드리프트 사례를 기준으로 정리한 정본 체크리스트다. 2026-06-13 기준 전수 스캔 결과(추적 1935개 + 미추적 후보 3개, hit 159개)는 [버전 표면 전체 파일 감사 기록](adaptive-html-final-version-surface-audit-20260613.md)에 남겼다.

| 구분 | 파일/경로 | 필수 수정/확인 내용 |
|---|---|---|
| 단일 출처 | `skills/adaptive-html-final/manifest.json` | `version`, `examples.version`, `examples.purpose`의 인라인 버전, `changes[0]`, `releases[0]`, `updated`, 필요 시 `quality.governance_count`/`required_gates` |
| 스킬 본체 | `skills/adaptive-html-final/SKILL.md` | 상단 `> Version ...`, 현행 기준선/완료 게이트 문구, 버전 하드코딩 표면 |
| 변경 이력 | `skills/adaptive-html-final/CHANGELOG.md` | 승인 전에는 `Unreleased`; 승인 후에만 `## vX.Y.Z (YYYY-MM-DD)`로 승격 |
| 루트 README | `README.md` | badge, 최근 업데이트, 운영 기준, 갤러리 현행 문구, 프로젝트 트리, 버전 히스토리 표, 게이트 현황, 로컬 확인 주석, footer subtext |
| 에이전트 진입점 | `AGENTS.md` | 현재 버전, 버전 업데이트 체크리스트, 불변식의 현재 버전 문구, 현행 examples 기준선 문구, 이 가이드 링크 |
| 사용자 가이드 | `Guide.md` | 대상 스킬 버전, 버전 표, 빌드 완성도 기준선, 한 줄 요약 |
| 스킬 README | `skills/adaptive-html-final/README.md` | 존재 시 현행 버전/설치/패키지 문구 확인 |
| 참조 문서 | `skills/adaptive-html-final/references/*.md` | “현행 vX.Y.Z”, “현재 스킬 자산 기준”, 게이트 수/기준선 문구 확인. 특히 `visual-html-system.md`, `quality-gates.md` |
| 예제 HTML | `skills/adaptive-html-final/examples/*.html` | header meta/generated row/footer의 `adaptive-html-final vX.Y.Z` visible text. CSS 주석의 역사적 버전은 무조건 변경하지 않음 |
| 예제 index | `skills/adaptive-html-final/examples/index.html` | 갤러리 meta, 링크/설명, favicon 등 새 참조 파일 포함 여부 |
| source manifest | `skills/adaptive-html-final/examples/sources/adaptive-html-final-manifest.json` | `manifest.json`과 JSON 내용 동일해야 함 |
| source snapshots | `skills/adaptive-html-final/examples/sources/assets/*.css`, `css-integrity.json` | CSS 자산 변경 시만 해시/스냅샷 동기화 |
| 검증기 | `skills/adaptive-html-final/scripts/validate_output.py` | 버전 표면·패키지 byte-match·릴리스 승인 게이트가 새 표면을 커버하는지 확인 |
| 완료 게이트 | `skills/adaptive-html-final/scripts/completion_check.py`, `quality_contract_check.py` | 새 필수 게이트가 있으면 completion에 포함 여부 확인 |
| 거버넌스 테스트 | `skills/adaptive-html-final/tests/test_governance_gates.py` | fixture 버전은 가능하면 현재 버전이 아닌 중립값 사용. `manifest.quality.governance_count`와 실측 count 일치 |
| 패키지 | `skills/adaptive-html-final.skill` | 마지막에 재패키징. zip 내부 `adaptive-html-final/` 파일이 워킹트리와 byte-match해야 함 |
| 개발 계획 | `dev-plan/implement_*.md` | 진행 중 계획은 역사 기록으로 둔다. “현행”으로 읽히는 버전만 수정, 과거 기준선은 보존 |
| 산출물 | `output/**` | 기본적으로 수정하지 않음. 사용자가 특정 output을 최신 산출물로 재발행/승격하라고 할 때만 별도 산출물로 처리 |
| 템플릿 카탈로그 | `templates/**` | 스킬 정본으로 승격된 템플릿만 확인. 역사적 catalog는 무조건 현재 버전으로 치환하지 않음 |

## 4. 전체 파일 스캔 명령

버전업 전후에 반드시 저장소 루트에서 실행한다.

```bash
# 현재 정본 버전 확인
python3 - <<'PY'
import json
print(json.load(open('skills/adaptive-html-final/manifest.json'))['version'])
PY

# 버전/현행 표면 전체 스캔 — output은 역사 산출물이므로 별도 판단
rg -n "5\\.10\\.[0-9]|v5\\.10\\.[0-9]|adaptive-html-final v|Generated by adaptive-html-final|Version 5\\.10|\"version\"\\s*:" \
  . --glob '!node_modules/**' --glob '!.git/**' --glob '!*.skill'

# 현행 스킬 표면만 집중 스캔
rg -n "5\\.10\\.[0-9]|v5\\.10\\.[0-9]|adaptive-html-final v|Generated by adaptive-html-final|Version 5\\.10|\"version\"\\s*:" \
  AGENTS.md Guide.md README.md skills/adaptive-html-final --glob '!*.skill'
```

## 5. 버전업 표준 절차

1. 변경 작업을 현재 버전으로 완료한다. 버전을 먼저 올리지 않는다.
2. `CHANGELOG.md`에는 `## Unreleased`로만 기록한다.
3. 전체 검증을 현재 버전으로 통과시킨다.
4. 사용자에게 버전업 승인 여부를 확인한다.
5. 승인되면 `dev-plan/release-approval-vX.Y.Z.md`를 남긴다.
6. 위 3장의 모든 표면을 한 번에 수정한다.
7. `examples/sources/adaptive-html-final-manifest.json`을 `manifest.json`과 동기화한다.
8. `skills/adaptive-html-final.skill`을 재패키징한다.
9. 아래 검증 명령을 모두 통과시킨다.
10. 마지막으로 `rg` 스캔으로 구버전/미승인 신버전 표면이 없는지 확인한다.

## 7. 금지 패턴

| 금지 | 이유 |
|---|---|
| 예제 1개 수정 후 patch version bump | 모든 표면 동기화 비용이 크고 회귀 위험이 높음 |
| `manifest.version`만 먼저 수정 | source manifest, examples, README, `.skill`이 즉시 stale 상태가 됨 |
| output의 과거 버전을 현재 버전으로 일괄 치환 | output은 시점 고정 산출물이라 역사성이 깨짐 |
| 테스트 fixture에 현재 버전을 하드코딩 | 다음 릴리스 때 불필요한 표면 드리프트가 생김. 중립 버전 fixture 사용 |
| CHANGELOG를 새 버전으로 먼저 작성 | 승인되지 않은 릴리스처럼 보임. 먼저 `Unreleased` 사용 |

## 8. 이전 감사 결과 기록 (2026-06-13)

> 아래 항목은 2026-06-13 당시 v5.10.3 정합 감사를 남긴 역사 기록이다. 현행 버전은 항상 `skills/adaptive-html-final/manifest.json`을 단일 출처로 확인한다.

- 2026-06-13 당시 `origin/main`과 `HEAD`의 정본 버전은 `5.10.3`이었다.
- 로컬 작업 중 생긴 승인 없는 patch bump는 정본 표면에서 제거하고, 사용자가 명시한 정본 버전으로 다시 정합해야 한다.
- `output/`은 버전업 기준선이 아니며, 이번 가이드에서도 자동 수정 대상에서 제외한다.
- 버전 변경은 이 문서의 표면 목록을 모두 통과할 때만 허용한다.

## 9. 승인 릴리스 결과 기록 (2026-06-14)

- `dev-plan/release-approval-v5.10.4.md`가 존재하면 v5.10.4 승격은 승인된 릴리스로 취급한다.
- v5.10.4 승격 후 현행 정본 버전은 `manifest.json`의 `5.10.4`이며, README/AGENTS/Guide/SKILL/manifest/examples/source snapshot/`.skill` 패키지 표면이 이 버전과 일치해야 한다.
