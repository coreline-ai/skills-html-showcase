코드 비교

한 문제, 세 가지 구현 접근

문제: 중복 없는 정수 배열에서 두 수의 합이 target이 되는 인덱스 쌍 찾기. 세 접근의 코드·장단점·트레이드오프를 나란히 비교합니다.

A

완전 탐색 (Brute Force)

O(n²) · 추가 메모리 없음

def two_sum(nums, target):
  for i in range(len(nums)):
    for j in range(i+1, len(nums)):
      if nums[i]+nums[j] == target:
        return [i, j]
  return []

▲ 장점

  • 구현이 단순, 버그 위험 낮음
  • 메모리 O(1)

▼ 단점

  • 큰 입력에서 느림
  • 중첩 루프 확장성 낮음
시간 O(n²) 공간 O(1) 읽기 쉬움
B

해시맵 1-pass 권장

O(n) · 메모리 트레이드

def two_sum(nums, target):
  seen = {}
  for i, n in enumerate(nums):
    need = target - n
    if need in seen:
      return [seen[need], i]
    seen[n] = i
  return []

▲ 장점

  • 선형 시간, 단일 순회
  • 대규모 입력에 안정적

▼ 단점

  • O(n) 추가 메모리
  • 해시 충돌 의존
시간 O(n) 공간 O(n) 실무 기본
C

정렬 + 투 포인터

O(n log n) · 인덱스 보존 필요

def two_sum(nums, target):
  arr = sorted(enumerate(nums), key=lambda x: x[1])
  l, r = 0, len(arr)-1
  while l < r:
    s = arr[l][1] + arr[r][1]
    if s == target: return [arr[l][0], arr[r][0]]
    l, r = (l+1, r) if s<target else (l, r-1)
  return []

▲ 장점

  • 정렬 데이터에 재사용 용이
  • 공간 O(1)~O(n)

▼ 단점

  • 정렬 비용 발생
  • 원본 인덱스 추적 복잡
시간 O(n log n) 공간 O(n) 정렬 의존
