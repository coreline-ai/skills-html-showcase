# Writing System

## Universal

- 사실, 해석, 추론을 분리한다.
- 확인되지 않은 최신 정보는 단정하지 않는다.
- 첫 3문단 안에 독자가 계속 읽을 이유를 만든다.
- 마지막에는 행동 제안 또는 체크리스트를 둔다.

## Beginner

풀어쓰기, 첫 등장 용어 설명, 일상 비유, 흔한 오해를 우선한다. 압축보다 이해를 선택한다.

## Expert

결론, 판단 기준, 리스크, 검증 기준을 우선한다. 감상보다 의사결정에 필요한 정보를 앞에 둔다.

## Article

공개 매거진 글처럼 lead, 맥락, 주장, 사례, takeaway 순서로 전개한다.

## Education

학습 목표, 사전 개념, 예제, 실습, 퀴즈, 정답 해설이 있어야 한다.

## Blog

Hook → 문제 → 관점 → 사례 → 실행 → CTA 흐름을 따른다. 과장된 마케팅 문구보다 실제 경험과 판단을 우선한다.

## Audit

목적, 트리거, 입력/출력, 워크플로우, 금지 규칙, 품질 게이트, 완료 기준을 빠짐없이 본다.

## GitHub Analysis

GitHub 저장소 분석은 README를 예쁘게 다시 쓰는 작업이 아니라 “이 저장소를 이해·실행·채택·감사해도 되는가?”를 판단하게 만드는 실사 리포트다.

필수 원칙:

- **질문 중심 목차**: 무엇인가, 바로 실행 가능한가, 어디를 보면 되는가, 살아 있는 프로젝트인가, 라이선스/보안 리스크는 무엇인가, 다음 행동은 무엇인가.
- **FACT / INFERENCE / UNKNOWN 분리**: README, repository metadata, files, releases, issues, PRs, contributors, topics, license처럼 관측 가능한 값만 FACT로 쓴다. 내부 보안 설정, 실제 취약점, 비공개 로드맵은 UNKNOWN으로 둔다.
- **근거 링크/근거 필드**: 핵심 판단 카드에는 “근거” 또는 “확인 위치”를 함께 둔다. 출처가 없으면 점수화하지 않는다.
- **채택 판단 우선**: 별점/포크 수만 앞세우지 말고 quickstart 재현성, 최근 활동, 테스트/CI 흔적, 릴리스/버전 정책, 라이선스 명확성, 보안 안내를 더 중요하게 본다.
- **실행 계획 마무리**: 마지막은 사용/검토/보류/대체 탐색 중 하나의 권장 행동과 3~5개 후속 체크리스트로 끝낸다.

권장 블록:

```text
verdict → repo identity → quickstart readiness → health signals
→ file/code tour → releases/activity → security/license
→ risk matrix → final decision → next actions → source limits
```

## Blog/SEO 상세 규칙 (adaptive-html-blog-writer 계승)

### 제목 생성 규칙 (4계열, 5~10개 제안)

```text
검색형: 핵심 키워드가 앞에 온다.
클릭형: 궁금증/대비/실수/변화를 강조한다.
전문가형: 구조, 기준, 설계, 분석 같은 단어를 쓴다.
초보자형: 쉽게, 처음부터, 한 번에 이해 같은 표현을 쓴다.
```

금지: "충격/대박/절대/무조건" 같은 과장어, 본문에서 증명하지 못하는 제목, 근거 없는 숫자.

### 도입부 규칙

3유형 중 하나를 선택한다 — ① 문제 제기형(독자의 혼란에서 시작) ② 변화 감지형(최근 흐름에서 시작) ③ 실전 사례형(구체 상황에서 시작). 첫 문단은 3~5문장을 넘기지 않는다.

### 본문 밀도

```text
설명 50% · 예시 20% · 오해/주의 15% · 정리/행동 15%
```

문단 하나는 3~5문장 이내. 길어지면 H3 또는 bullet로 분리한다. 어려운 개념은 한 번 이상 쉬운 비유로 설명하고, 중간마다 독자의 오해·흔한 실수·반론을 선제적으로 다룬다. 마지막은 요약 + 다음 행동.

### 톤 매핑

| 톤 | 사용 상황 |
|---|---|
| 친근한 설명체 | 초보자/일반 블로그 |
| 전문가 분석체 | 기술/비즈니스 블로그 |
| 튜토리얼체 | 개발/사용법 글 |
| 칼럼체 | 의견/트렌드 글 |
