02 · Expert Briefing Report

MCP Gateway 설계 진단 리포트

여러 MCP 서버를 하나의 게이트웨이로 묶을 때 필요한 권한, 캐시, 관측성, 장애 격리 기준을 전문가용으로 정리합니다.

모드: expert레이아웃: briefing report폭: 980px

1Executive Summary

핵심 판단

단일 등록 UX는 좋지만 내부 권한 경계가 없으면 위험합니다.

우선순위

registry, auth, audit log가 먼저입니다.

최대 리스크

도구 권한이 사용자/프로젝트 단위로 분리되지 않는 구조입니다.

2권장 구조

계층역할검증 기준
Gateway요청 라우팅도구별 allow/deny
Registry서버/도구 메타데이터버전과 owner 기록
Audit호출 추적누가 어떤 도구를 호출했는지 기록

3Risk Matrix

High

모든 MCP 도구를 한 번에 노출하면 프롬프트 인젝션 피해 범위가 커집니다.

Medium

캐시 무효화 기준이 없으면 오래된 tool schema로 호출 실패가 늘어납니다.

Low

관리자 UI 부재는 초기에는 수동 설정으로 보완할 수 있습니다.

4개선 우선순위

  1. tool registry schema
  2. project-level permission
  3. audit log
  4. token vault
  5. observability dashboard

결론Final Recommendation

MCP Gateway는 편의 기능보다 권한 경계와 관측성을 먼저 설계해야 합니다.
