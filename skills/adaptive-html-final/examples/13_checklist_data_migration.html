Overview

데이터 마이그레이션은 "옮기는 것"이 아니라 "언제든 되돌릴 수 있게 옮기는 것"이다. 한 번 손상되거나 유실된 운영 데이터는 복구 비용이 크고, 일부는 회복 자체가 불가능하다. 그래서 이전 작업은 항상 복귀 경로를 먼저 확보한 뒤 시작한다.

이 플레이북은 "성공적으로 옮긴 것처럼 보이는 작업"이 아니라 검증된 백업, 양쪽 동시 기록(dual-write), 행 단위 정합성 검증, 안전한 컷오버, 즉시 롤백이 모두 준비되었는지 판단하는 마이그레이션 회의용 기준 문서다.

1마이그레이션 5대 원칙

P0(데이터 손실·정합성 위반)이 남아 있으면 컷오버하지 않고, P1 위험은 owner와 완화 일정이 있을 때만 진행한다.

사전 백업

이전 시작 전 복원 가능한 백업을 확보하고, 실제로 복원해 본다. 복원해 보지 않은 백업은 백업이 아니다.

dual-write

전환 기간 동안 구·신 저장소에 동시에 기록해, 어느 쪽으로도 읽기를 전환할 수 있는 상태를 유지한다.

검증

행 수·체크섬·샘플 비교로 정합성을 측정한다. 불일치 0건이 아니면 컷오버하지 않는다.

컷오버

읽기 경로를 신규로 전환하는 단일 결정 지점. 점진 비율 전환과 즉시 되돌림 경로를 함께 준비한다.

롤백

트리거 조건을 수치로 미리 정하고, 충족되면 토론 없이 구 저장소로 읽기를 되돌린다.

2단계별 점검표

사전 백업 → dual-write → 검증 → 컷오버 → 롤백 다섯 단계마다 확인 항목·담당·상태를 고정한다.

점검표는 "무엇을 했는가"가 아니라 "각 항목이 지금 어떤 상태인가"를 한눈에 보여주는 도구다. 항목마다 미시작 → 진행 중 → 대기 → 완료 상태를 두고, 핵심 항목이 하나라도 대기(blocked)이면 컷오버 회의에서 자동으로 No-Go가 된다.

각 항목은 반드시 증거(evidence)를 가진다. "확인했다"는 보고가 아니라 복원 리허설 로그, 검증 리포트, diff 샘플처럼 다른 사람이 다시 열어볼 수 있는 산출물을 남긴다. 상태 표식은 텍스트 ✓(완료)와 대기로만 표기하며 별도 인터랙션은 없다.

상태 어휘

대기(blocked) vs 보류(pending)

대기는 검증 결과 정합성 기준을 위반해 수정 없이는 완료가 불가능한 상태다. 보류는 아직 확인하지 못해 판단을 내릴 수 없는 상태로, 보류 항목이 남아 있으면 "모름"이므로 역시 컷오버하지 않는다.

3품질 게이트

검증 결과를 차단·경고·통과 세 등급으로 나눠 컷오버 여부를 자동 판정한다.

품질 게이트는 마이그레이션 검증 결과를 차단(block) · 경고(warn) · 통과(pass) 세 등급으로 나눈다. 핵심은 "대부분 옮겨졌다"가 아니라 정합성 불일치가 0건인가에 있다. 99.9%가 일치해도 0.1%에 결제·잔액 같은 핵심 행이 어긋나면 게이트는 차단이다.

게이트는 사람이 매번 눈으로 판단하지 않도록 수치 기준으로 고정한다. 행 수 차이, 체크섬 불일치 건수, dual-write 쓰기 실패율, 복제 지연(lag)에 임계값을 두고, 미달이면 자동으로 경고 또는 차단 등급이 매겨진다.

차단

핵심 테이블 체크섬 불일치 또는 행 수 불일치 1건 이상. 컷오버 중단, 원인 수정 후 재검증.

경고

비핵심 컬럼 차이·복제 지연 상승. owner와 완화 일정이 있을 때만 축소 비율로 진행.

통과

전 테이블 불일치 0건, dual-write 실패율 0, lag 임계 이내. 다음 단계 진행.

흔한 함정

"대부분 옮겨졌다"로 핵심 행 불일치를 덮지 마라

전체 일치율 99.9%여도 결제·권한·잔액처럼 회복 불가능한 행이 단 1건 어긋나면 그 1건이 사고를 만든다. 게이트는 평균 일치율이 아니라 핵심 테이블 불일치 0건을 기준으로 판정해야 한다.

4위험 신호와 안전 신호

컷오버를 멈춰야 하는 위험 신호와, 안전하게 진행해도 되는 신호를 미리 구분해 둔다.

대시보드에서 어떤 숫자를 위험으로 읽을지 사전에 합의한다. 같은 지표라도 "이 값이면 멈춘다 / 이 값이면 간다"를 미리 정해 두면, 사고 순간에 사람의 즉흥 판단에 의존하지 않는다.

위험 신호 · STOP

하나라도 보이면 컷오버를 중단하고 롤백 검토

핵심 테이블 행 수·체크섬 불일치 1건 이상, dual-write 쓰기 실패가 누적되는 중, 복제 지연(lag)이 임계를 넘어 계속 벌어지는 중, 복원 리허설 미완료, 롤백 토글이 staging에서 미검증 — 이 중 어느 하나라도 해당하면 진행하지 않는다.

안전 신호 · GO

모두 충족될 때만 다음 비율로 전환

검증 불일치 0건이 두 차례 연속 측정에서 유지, dual-write 실패율 0이 관찰 기간 내내 지속, 복제 지연이 임계 이내로 안정, 복원 리허설과 롤백 drill이 각각 1회 이상 성공으로 기록됨 — 네 신호가 동시에 충족될 때만 컷오버 비율을 올린다.

5컷오버와 롤백 절차

읽기 소스를 점진 전환하고, 트리거 충족 시 즉시 구 저장소로 되돌리는 절차를 코드로 고정한다.

컷오버의 목적은 "문제가 생기면 작게 생기게" 만드는 것이다. 쓰기는 dual-write로 양쪽에 계속 들어가는 상태에서, 읽기 소스만 1% → 25% → 100%로 단계적으로 옮긴다. 어느 단계든 위험 신호가 보이면 읽기 소스를 구 저장소로 되돌린다. 쓰기가 양쪽에 살아 있으므로 데이터 손실 없이 즉시 복귀할 수 있다.

아래 의사코드는 컷오버 흐름을 사람과 자동화가 동일하게 읽을 수 있도록 정리한 것이다. 기본값은 항상 안전한 쪽(읽기=구 저장소, dual-write ON)으로 둔다.

cutover(table):
    assert backup.restore_verified            # 복원 리허설 통과 전제
    assert dual_write.enabled                  # 양쪽 쓰기 유지
    if verify(table).mismatch > 0:             # 정합성 검증
        return STOP("불일치 수정 후 재검증")    # 차단 경로

    for pct in [1, 25, 100]:                    # 읽기 소스 점진 전환
        read_source.shift(new_store, pct)
        observe(soak_time)                      # 관찰 기간(피크 포함)
        if risk_signal():                       # 위험 신호 감지
            read_source.shift(old_store, 100)   # 롤백: 즉시 구 저장소로
            return ROLLBACK("트리거 충족, 토글 복귀")

    dual_write.keep(retention_window)           # 안정화 기간 동안 유지
    return DONE("컷오버 완료, 관찰 지속")

정상 경로

검증 0건 통과 → 1%·25%·100% 단계 전환 → soak time 안정 → dual-write 유지 후 종료.

차단 경로

검증 불일치 발생. 컷오버 시작 전 중단, 원인 수정 후 같은 테이블부터 재검증.

롤백 경로

위험 신호·트리거 충족. 읽기 소스를 구 저장소로 즉시 토글, 데이터 손실 없이 복귀.

Rollback Rule

롤백 트리거 1건이라도 충족되면 토론 없이 즉시 읽기 소스를 구 저장소로 되돌린다.

완화로 시간을 버는 것은 허용하지만, 트리거 조건은 사람의 판단이 아니라 미리 정한 수치로 자동 결정한다. dual-write가 살아 있는 한 롤백은 데이터 손실을 만들지 않는다. 완료 기준을 만족하기 전에는 컷오버를 재개하지 않는다.

FINAL APPROVAL

컷오버 최종 승인 기준

아래 다섯 조건이 동시에 충족될 때만 1% 그림자 읽기 컷오버를 승인한다. 하나라도 비면 No-Go이며, 100% 전환은 7일 안정화 관찰과 회고가 끝난 뒤 별도 승인한다.

  1. 사전 백업 — 복원 리허설 1회 성공, RPO·RTO 측정·기록 완료.
  2. dual-write — 구·신 저장소 동시 기록 가동, 쓰기 실패율 0, 읽기 소스 토글 가능.
  3. 검증 — 핵심 테이블 행 수·체크섬·샘플 불일치 0건이 연속 2회 유지.
  4. 컷오버 — 1%·25%·100% 점진 전환 계획과 soak time 기준 확정.
  5. 롤백 — 트리거 수치 정의 완료, staging에서 롤백 drill 1회 성공 기록.
