정규식(Regex) 실무 레퍼런스

메타문자, 앵커, 수량자, 그룹, 룩어라운드, 플래그를 한 화면에서 찾아 쓰는 실무용 정규식 참조 문서다. 패턴을 외우는 대신 "무엇이 어떤 위치를, 몇 번, 어떻게 매칭하는가"를 표와 예시로 빠르게 확인한다.

reference_htmlreference-manual.htmlprofile autoadaptive-html-final무 JS
Overview

정규식은 "위치(anchor)·문자 집합(class)·반복(quantifier)·묶음(group)"의 조합이다. 복잡한 패턴도 이 네 축으로 분해하면 읽고 디버깅할 수 있다. 이 레퍼런스는 메타문자와 이스케이프 규칙을 먼저 고정하고, 앵커와 수량자로 매칭 범위를 좁힌 뒤, 그룹과 룩어라운드로 "캡처할 것"과 "조건으로만 볼 것"을 분리하며, 마지막으로 플래그로 전체 동작 모드를 바꾸는 순서로 구성했다. 표기는 PCRE/JavaScript 계열을 기준으로 하고, 방언 차이는 그때그때 명시한다.

정규식을 만날 때마다 토큰을 이 네 종류로 라벨링하면 의도가 드러난다. 예를 들어 ^\d{3}-\d{4}$는 위치(^...$ 전체 일치), 문자(\d 숫자), 반복({3}, {4} 횟수), 리터럴(-)의 조합이다. 새 패턴을 읽을 때는 항상 "이 토큰이 위치냐, 집합이냐, 반복이냐, 묶음이냐"를 먼저 묻는다.

1빠른 레퍼런스

패턴을 쓰기 직전에 가장 자주 확인하는 토큰을 한 표에 모았다. 나머지 절은 이 표의 항목을 깊게 푼 것이다.

가장 자주 쓰는 정규식 토큰
토큰의미분류예시 매칭
.개행을 제외한 임의의 한 문자문자a.c → abc, a9c
\d \w \s숫자 / 단어문자 / 공백문자 클래스\d+ → 2026
^ $줄(또는 문자열)의 시작·끝앵커^https? → 줄 시작의 http(s)
* + ?0회 이상 / 1회 이상 / 0~1회수량자colou?r → color, colour
{n,m}n회 이상 m회 이하 반복수량자\d{2,4} → 12~1234
(...)그룹화 + 캡처그룹(ab)+ → abab
a|b택일(or)그룹cat|dog → cat 또는 dog
[...]문자 집합 중 하나문자 클래스[aeiou] → 모음 하나

2메타문자와 문자 클래스

메타문자는 "문자 그 자체"가 아니라 "규칙"을 뜻하는 특수 기호다. 리터럴로 쓰려면 백슬래시로 이스케이프한다.

정규식에서 12개 정도의 기호(. ^ $ * + ? ( ) [ ] { } | \)는 특별한 의미를 가진다. 이들을 문자 그대로 매칭하려면 앞에 \를 붙인다. 예를 들어 가격의 점을 매칭하려면 .이 아니라 \.을 써야 한다. 반대로 문자 클래스(축약 클래스)는 자주 쓰는 문자 집합을 한 글자로 줄여 둔 것이다.

축약 문자 클래스와 대응 집합
토큰의미동등한 집합부정형
\d숫자[0-9]\D (숫자 아님)
\w단어 문자[A-Za-z0-9_]\W (단어 아님)
\s공백류[ \t\r\n\f\v]\S (공백 아님)
.임의 한 문자개행 제외(기본)[^\n]과 유사
[a-z]범위 집합소문자 하나[^a-z] (그 외)

문자 클래스 안에서는 규칙이 달라진다. [...] 대괄호 안에서는 대부분의 메타문자가 리터럴이 된다. 즉 [.+*]는 점·플러스·별표 세 글자 중 하나를 뜻한다. 단 ], ^(맨 앞일 때 부정), -(범위 구분), \는 클래스 안에서도 특별하므로 위치와 이스케이프에 주의한다. 예: [-+]처럼 하이픈을 맨 앞이나 맨 뒤에 두면 리터럴 하이픈이 된다.

3앵커와 경계

앵커는 문자를 소비하지 않고 "위치"만 주장한다. 폭이 0인 토큰(zero-width)이라는 점이 핵심이다.

앵커는 매칭 커서가 특정 위치에 있는지를 확인할 뿐, 어떤 글자도 잡아먹지 않는다. 이 때문에 ^와 $로 양끝을 고정하면 "부분 일치"가 아니라 "전체 일치"를 강제할 수 있다. 입력 검증에서 가장 흔한 버그가 바로 이 앵커 누락이다.

앵커와 경계 토큰
토큰주장하는 위치비고
^문자열(또는 줄)의 시작m 플래그면 각 줄 시작
$문자열(또는 줄)의 끝끝 개행 직전에도 일치할 수 있음
\b단어 경계\w와 비\w 사이
\B단어 경계가 아닌 곳단어 내부
\A \z \Z문자열 절대 시작·끝PCRE/Python, JS는 미지원
주의
앵커 없는 검증은 "포함"만 확인한다

/\d{4}/로 "4자리 숫자인지" 검사하면 abc1234xyz도 통과한다. 부분 문자열에 4자리 숫자가 들어 있기 때문이다. "입력 전체가 정확히 4자리 숫자"를 원하면 반드시 /^\d{4}$/처럼 양끝을 앵커로 고정한다. 입력 검증에서 앵커 누락은 가장 흔하고 위험한 실수다.

4수량자와 탐욕/게으름

수량자는 "직전 토큰을 몇 번 반복하는가"를 정한다. 같은 횟수라도 탐욕(greedy)·게으름(lazy)·소유(possessive)에 따라 매칭 범위가 달라진다.

수량자 종류와 반복 의미
수량자반복 횟수탐욕(기본)게으름(? 추가)
*0회 이상**?
+1회 이상++?
?0~1회???
{n}정확히 n회고정고정
{n,}n회 이상{n,}{n,}?
{n,m}n~m회{n,m}{n,m}?

탐욕 수량자는 가능한 한 많이 먹은 뒤 필요하면 되돌린다(backtracking). 게으름 수량자는 가능한 한 적게 먹고 필요할 때만 늘린다. HTML 태그를 잡을 때 차이가 극명하다.

탐욕 <.*>

입력 <b>hi</b>에서 .*가 끝까지 먹어 <b>hi</b> 전체를 한 덩어리로 잡는다. 첫 태그만 원했다면 과매칭이다.

게으름 <.*?>

같은 입력에서 .*?가 최소로 먹어 <b>만 잡는다. "가장 가까운 닫는 기호까지"가 의도일 때 쓴다.

소유 <[^>]*>

되돌림 없이 닫는 기호가 아닌 문자만 먹는다. 백트래킹 폭주를 구조적으로 막는 가장 안전한 방식이다.

# 같은 입력, 다른 수량자
입력:  <b>hi</b>
<.*>    →  <b>hi</b>     (탐욕: 전체)
<.*?>   →  <b>           (게으름: 최소)
<[^>]*> →  <b>           (소유적: 되돌림 없음)
주의
중첩 수량자는 치명적 백트래킹(ReDoS)을 부른다

(a+)+$, (.*)*처럼 반복 안에 반복을 넣고 뒤에 실패 조건이 오면, 엔진이 지수적으로 경우의 수를 시도하다 멈춘다. 가능하면 소유 수량자(a++)나 원자 그룹((?>...)), 또는 부정 문자 클래스([^x]*)로 되돌림 자체를 차단한다.

5그룹과 캡처

괄호는 "묶기"와 "캡처"를 동시에 한다. 캡처가 필요 없으면 비캡처 그룹으로 성능과 가독성을 챙긴다.

그룹 종류 비교
문법이름캡처 여부참조 방법
(abc)캡처 그룹예 (번호)치환 $1, 역참조 \1
(?:abc)비캡처 그룹아니오묶기만, 참조 불가
(?<y>abc)이름 캡처 그룹예 (이름)$<y>, \k<y>
\1역참조—앞 캡처와 같은 문자열 재매칭

비캡처 그룹은 택일을 묶거나 수량자를 적용할 때처럼 "캡처는 필요 없고 묶기만 필요한" 경우에 쓴다. 캡처 그룹이 많아지면 $1, $2 번호가 헷갈리므로, 치환이나 추출이 목적이면 이름 캡처가 유지보수에 유리하다.

# 날짜를 이름 그룹으로 캡처해 순서 바꾸기
패턴:   (?<y>\d{4})-(?<m>\d{2})-(?<d>\d{2})
입력:   2026-06-05
치환:   $<d>/$<m>/$<y>
결과:   05/06/2026

# 역참조로 따옴표 짝 맞추기
패턴:   (['"]).*?\1     # 같은 따옴표로 닫히는 구간
입력:   "a" 'b'        → "a"  와  'b'  각각 일치

6룩어라운드 비교

룩어라운드는 "주변 조건"만 확인하고 문자를 소비하지 않는다(zero-width). 캡처하지 않고 조건만 걸 때 쓴다.

룩어라운드 4종 비교
문법이름방향의미예시
(?=...)긍정 전방탐색오른쪽뒤가 ...여야 함\d+(?= ) 공백 앞 숫자
(?!...)부정 전방탐색오른쪽뒤가 ...가 아니어야 함foo(?!bar) bar 안 붙은 foo
(?<=...)긍정 후방탐색왼쪽앞이 ...여야 함(?<=\$)\d+ $ 뒤 숫자
(?<!...)부정 후방탐색왼쪽앞이 ...가 아니어야 함(?<!\d)\d{3} 숫자 안 붙은 3자리
활용
소비하지 않는 조건으로 "추출 폭"을 정확히 만든다

가격 $1500에서 숫자만 뽑고 싶을 때 (?<=\$)\d+를 쓰면 $는 매칭 결과에 포함되지 않고 1500만 잡힌다. 통화 기호를 캡처 그룹으로 잡은 뒤 버리는 것보다 후방탐색이 의도를 명확히 드러낸다. 단, 후방탐색의 가변 길이 지원은 엔진마다 다르므로(JavaScript는 지원, 일부 엔진은 고정 길이만) 방언을 확인한다.

# 천 단위 콤마 넣기: 숫자를 소비하지 않고 위치만 찾는다
패턴:   \B(?=(\d{3})+(?!\d))
입력:   1234567
치환:   ,
결과:   1,234,567

7플래그

플래그(모디파이어)는 패턴 전체의 동작 모드를 바꾼다. 같은 패턴이라도 플래그에 따라 결과가 달라진다.

주요 플래그와 효과
플래그이름효과주의
iignore case대소문자 무시유니코드는 u와 함께
gglobal모든 일치 반복 탐색JS에서 lastIndex 상태 유지
mmultiline^ $가 각 줄에 적용전체 시작/끝은 \A \z
sdotall.이 개행도 매칭여러 줄 블록 잡을 때 필수
uunicode코드포인트 단위, \p{...} 허용이모지·서러게이트 안전
xextended패턴 내 공백·주석 무시긴 패턴 가독성용(JS 미지원)
  • g의 함정 — JavaScript에서 g 플래그가 붙은 정규식 객체는 lastIndex를 기억하므로, 같은 객체로 test()를 반복 호출하면 결과가 번갈아 바뀐다. 검증용에는 g를 빼거나 매번 새 객체를 만든다.
  • m vs s 혼동 — m은 ^ $의 줄 적용이고, .이 개행을 먹게 하는 것은 s다. 여러 줄 블록을 한 덩어리로 잡으려면 s가 필요하다.
  • 인라인 플래그 — (?i), (?i:...)처럼 패턴 일부에만 플래그를 켤 수 있는 엔진도 있다(JS는 인라인 미지원, PCRE/Python 지원).

8실무 예시 패턴

자주 필요한 패턴을 분해와 함께 정리했다. 입력 검증은 항상 앵커로 양끝을 고정한다.

# 1) 한국 휴대폰 번호 (010-1234-5678, 01012345678)
^01[016789]-?\d{3,4}-?\d{4}$

# 2) 이메일 (실무용 근사치 — 100% 표준은 아님)
^[\w.+-]+@[\w-]+(\.[\w-]+)+$

# 3) URL slug (소문자·숫자·하이픈, 끝/시작 하이픈 금지)
^[a-z0-9]+(?:-[a-z0-9]+)*$

# 4) HEX 색상 (#fff 또는 #ffffff)
^#(?:[0-9a-fA-F]{3}|[0-9a-fA-F]{6})$

# 5) ISO 날짜 (YYYY-MM-DD)
^\d{4}-(?:0[1-9]|1[0-2])-(?:0[1-9]|[12]\d|3[01])$

# 6) 공백/탭 트림 (양끝 공백 제거용 매칭)
^\s+|\s+$
분해 예시
^01[016789]-?\d{3,4}-?\d{4}$

^...$로 전체 일치를 강제하고, 01 리터럴 뒤 [016789]로 통신사 자리, -?로 하이픈을 선택적(있어도 없어도)으로 허용, \d{3,4}로 국번 3~4자리, 마지막 \d{4}로 가입자 번호 4자리를 잡는다. 위치·문자·반복이 한 줄에 모두 들어 있다.

9흔한 실수

정상 입력을 떨어뜨리거나, 위험한 입력을 통과시키거나, 엔진을 멈추게 하는 단골 패턴이다.

  • 앵커 누락 — \d{4}로 "4자리 숫자인지" 검사하면 abc1234도 통과한다. 전체 일치는 ^\d{4}$.
  • .을 이스케이프 안 함 — 3.14를 잡으려고 3.14를 쓰면 3x14도 매칭된다. 리터럴 점은 3\.14.
  • 탐욕 과매칭 — ".*"로 따옴표 문자열을 잡으면 한 줄의 첫 따옴표부터 마지막 따옴표까지 통째로 먹는다. "[^"]*" 또는 ".*?"를 쓴다.
  • 중첩 반복(ReDoS) — (a+)+$, (\w+\s?)*$는 실패 입력에서 지수적으로 느려진다. 소유 수량자·원자 그룹·부정 클래스로 백트래킹을 막는다.
  • 클래스 안 하이픈 위치 — [a-z-A-Z]처럼 가운데 하이픈은 범위로 해석돼 의도와 다르게 동작한다. 리터럴은 맨 앞·맨 뒤([A-Za-z-])에 둔다.
  • g 상태 누수 — JS에서 g 정규식 객체를 재사용한 test()는 lastIndex 때문에 true/false가 번갈아 나온다. 검증엔 g를 빼라.
Anti-pattern
정규식으로 임의 HTML 전체를 파싱하려는 시도

중첩·임의 속성·주석·CDATA가 있는 HTML은 정규 언어가 아니므로 단일 정규식으로 안전하게 파싱할 수 없다. 태그 추출 같은 한정된 작업만 정규식으로 하고, 구조 분석은 전용 파서(DOM/HTML 파서)를 쓴다.

분류별로 핵심 토큰을 한 번에 훑는다. 패턴을 쓰다 막히면 이 표로 돌아온다.

바로 적용하기

  1. 지금 쓰는 입력 검증 정규식에 ^ $ 앵커가 빠진 곳이 없는지 점검한다.
  2. 리터럴로 쓰려던 .이 이스케이프됐는지(\.) 확인한다.
  3. 탐욕 수량자 .*를 게으름(.*?)이나 부정 클래스([^x]*)로 바꿀 수 있는지 본다.
  4. 사용 중인 엔진(JS·PCRE·Python)의 후방탐색·인라인 플래그·x 지원 여부를 확정한다.
Source Note

표기는 PCRE/JavaScript 계열을 기준으로 했으며, 후방탐색 가변 길이·인라인 플래그·\A \z·x 모드 등은 엔진(방언)마다 지원이 다르다. 실제 적용 전 사용하는 언어·라이브러리의 문서를 확인한다. 이 문서는 동작 JS 없이 CSS-only 컴포넌트로 작성되었다.
