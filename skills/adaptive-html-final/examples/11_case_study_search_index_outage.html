Overview

색인 파이프라인을 검색 서빙과 한 클러스터에 두면, 색인이 멈출 때 검색은 "조용히" 오래된 결과를 반환한다. 03:12 KST 색인 재구축 작업이 디스크 포화로 중단됐지만 검색 API는 계속 200을 반환했고, 그래서 6시간 동안 아무도 장애로 인지하지 못했다.

이 회고의 결론은 인덱서를 더 키우는 것이 아니라 색인 신선도(index freshness lag)를 1차 SLO 신호로 승격하고, 색인 경로와 검색 서빙 경로를 디스크·알림 차원에서 분리하는 것이다.

1사고 한 줄 요약

회고는 책임 추궁이 아니라, 다음 색인 정지에서 6시간이 아니라 6분 만에 보이게 하는 기록이다.

영향

새 상품·게시물 24만 건이 6시간 동안 검색에 노출되지 않았다. 검색은 죽지 않고 오래된 인덱스를 서빙해, 신규 등록 셀러의 노출 클레임이 집중됐다.

탐지

API 가용성·5xx·지연은 모두 정상이라 자동 경보가 한 건도 울리지 않았다. 셀러 CS 문의가 시스템 신호보다 5시간 18분 먼저 도착했다.

원인

색인 재구축이 03:12 디스크 92% 포화로 중단됐고, 검색 서빙과 같은 노드의 디스크를 공유했다. freshness lag를 보는 알림이 없었다.

예방

freshness lag 알림, 색인/서빙 디스크 분리, 인덱서 dead-man switch, 증분 색인 재시도, 분기별 색인 정지 게임데이를 후속 액션으로 묶었다.

2왜 6시간 동안 아무도 몰랐나

가용성·지연·오류율이 모두 녹색이면, 대시보드는 "정상"이라고 거짓말한다.

이 사고의 핵심은 장애가 큰 게 아니라 장애가 모든 기존 알림의 사각지대에 정확히 들어맞았다는 점이다. 검색 API는 6시간 내내 200을 반환했고 p99 지연도 정상이었다. 무너진 것은 "응답"이 아니라 "응답의 신선도"였는데, 우리 SLO 어디에도 freshness가 없었다.

아래 표는 사고 6시간 동안 각 신호가 무엇을 보고했는지다. 모든 가용성 신호가 정상이라는 사실 자체가, 신선도라는 차원이 측정되지 않았다는 증거다.

6근본 원인

직접 원인은 디스크 포화지만, 근본 원인은 신선도를 측정하지 않았고 경로를 격리하지 않았던 것이다.

Direct Cause

공유 디스크 92% 포화로 인덱서 write가 실패했다. 색인 노드는 검색 서빙과 같은 볼륨을 공유해, 색인 재구축의 임시 세그먼트가 디스크를 밀어 올렸다.

Systemic Cause

SLO가 가용성 중심이었다. 응답·지연·5xx는 보였지만, 인덱스가 얼마나 오래됐는지(freshness lag)는 SLO·대시보드 어디에도 없어 6시간을 무증상으로 흘려보냈다.

  1. 측정 부재
    freshness lag가 SLO·알림에 없어 무증상 정지가 가능했다.
  2. 격리 부재
    색인 경로와 검색 서빙 경로가 같은 노드 디스크를 공유했다.
  3. 가드 부재
    인덱서가 재시도 루프에 빠져도 깨우는 dead-man switch가 없었다.
  4. 백프레셔 부재
    디스크 압박 시 색인 작업을 throttle·연기하는 안전장치가 없었다.
"검색이 응답한다"는 사실이, 6시간 동안 "검색이 옳다"는 착각을 떠받쳤다.

7재발 감지 지표

가용성보다 신선도를 앞에 둔다. 정상 응답이 곧 정확한 응답은 아니기 때문이다.

색인 freshness lag

마지막 색인 성공 이후 경과 시간을 1차 신호로 둔다. p95 10분 초과 시 경고, 30분 초과 시 SEV 후보로 본다.

인덱서 진행률

증분 색인 처리량과 재시도 카운터를 추적한다. 재시도가 분당 100회를 넘으면 정지 루프로 간주한다.

디스크 압박

색인 노드 디스크 사용률 80% 경고, 88% 즉시 조치. 색인/서빙 분리 후에도 양쪽을 독립 추적한다.

9회고 결론

핵심 교훈은 검색을 더 빠르게 만드는 것이 아니라, 검색이 "조용히 틀리는" 상태를 보이게 만드는 것이다.

Decision

검색 인덱스 freshness를 가용성과 동급의 1차 SLO로 승격한다. 색인 경로는 검색 서빙과 디스크를 공유하지 못하게 하고, 인덱서가 조용히 멈추면 사람보다 먼저 시스템이 깨어나도록 dead-man switch를 둔다.

  • 완료 기준은 "다시 안 멈춘다"가 아니라, 멈춰도 10분 안에 보이고 30분 안에 복구할 수 있는 구조다.
  • 고객이 5시간 먼저 감지한 사고는 신선도 신호가 없었다는 뜻이다. CS 키워드도 SLO 입력으로 취급한다.
  • "정상 응답"은 "정확한 응답"이 아니다. 가용성 녹색이 신선도 적색을 가리지 못하게 분리한다.

한 줄 정리. 좋은 회고의 산출물은 "더 잘 보겠다"가 아니라 다음에 더 빨리 보이고 더 좁게 멈출 수 있는 신호와 경로다. 위 액션의 완료 기준은 모두 이 한 문장으로 검증된다.

NEXT ACTION

바로 실행할 일

  1. freshness lag 알림을 배포한다(10분 초과 시 온콜 호출).
  2. 인덱서 dead-man switch를 런북에 넣는다.
  3. 색인과 검색 서빙의 디스크 볼륨을 분리한다.
  4. 30일 안에 색인 정지 게임데이를 진행한다.
