이 문서는 `adaptive-html-final`로 문서를 생성할 때 반복 발생하는 품질 결함을 닫기 위한 작업 범위를 고정하고, 구현이 목적 밖으로 확장되지 않도록 하기 위한 작업 문서다.

## 개발 목적

스킬 산출물에서 반복 보고된 결함을 **생성 강제 + 검증 강제**로 닫는다. 단, 신규 게이트를 무분별하게 추가하지 않고 **중복 검사 결과**에 따라 처리한다.

- 이미 전역 강제된 항목(C2a·C2b·C4a)은 **건드리지 않는다**(중복 방지).
- 모드 한정 게이트(C1·C3)는 **신설이 아니라 범위 승격**으로 닫되, C3는 전 모드가 아니라 **toc-required 콘텐츠 페이지**로 한정해 오탐을 막는다.
- 정적으로 잡을 수 있는 것(C2c 아이콘 순서, C4b overflow 가드)은 **정적 게이트**로, 못 잡는 렌더 결함(C2c 간격, C4b 짤림, C6 수직 리듬)은 **렌더 아티팩트 검증**으로 흡수한다.
- 변경 후 governance·validate·completion_check 무회귀를 보장한다. **현재 baseline = 124/124**(실측, 2026-06-13). governance 체크 수는 하드코딩 대신 Phase 6에서 재측정한다(카운트 드리프트 방지).

## 개발 범위

- **C1**: `header_contract_gate`의 `generated-row`+`lens-strip` 권고 → **필수**(전 `layout-*` 콘텐츠 페이지). 비-github 모드 `lens-strip` 의미 정의 + SKILL §6 헤더 흐름 명문화.
- **C3**: `*_toc_map_missing` 강제 로직을 공통 헬퍼로 추출해 **toc-required 콘텐츠 페이지에만** 적용. toc-required 판정은 **직접 섹션 h2 개수 ≥ 4(구조 기준)** 를 1차 기준으로 삼고(긴 문서 자동 포함·짧은 문서 오탐 차단), 모드 allowlist는 보조 예외로만 둔다(예: 분석 모드는 h2<4여도 강제).
- **C2c(정적)**: 직접 섹션 h2의 자식 순서 `body-icon → (num/no) → title` 정적 게이트 신설(`h2_icon_order_violation`).
- **C4b(정적)**: 긴 무공백 토큰/코드/표가 보호 없이 노출되는 패턴 정적 가드. 표 보호 wrapper 인정 집합 = **`.tbl`·`.table-scroll`·`.final-matrix`·`.mobile-card`**(components.css에서 `.tbl`도 `overflow-x:auto` 보호이므로 포함). R4 인정 집합에도 `.tbl` 추가(허용 확대=additive, 신규 실패 0).
- **C5**: `quality_contract_check.py`에 "정본 컴포넌트 클래스 없이 raw `<p>`/`<div>` 연속만으로 직접 섹션 본문 합성" 차단(붕어빵 게이트와 목적 중복 회피).
- **C2c(간격)·C4b(짤림)·C6**: `completion_check.py`를 **render-audit.json + screenshot artifact 검증** 방식으로 전환(Playwright 직접 실행 아님).
- 변경에 따른 examples 18종 점검·재인라인(해시 변동 시), 문서/버전 표면 동기화, governance 회귀 테스트 추가.

## output/ 영향 범위 원칙

- `output/`은 과거 생성 결과물·공개 데모·테스트 산출물이다. 스킬의 source of truth는 `skills/adaptive-html-final/`의 manifest/SKILL/assets/references/examples이며, `output/` 존재 자체가 스킬 생성 결과를 바꾸면 안 된다.
- 새 게이트의 기본 검증 기준선은 `skills/adaptive-html-final/examples/`와 이번에 새로 생성한 산출물이다. 과거 `output/` 전체는 자동 검증 대상이 아니며, 사용자가 특정 output을 지정했을 때만 최신 게이트로 검사한다.
- `output/2026-06-04/final_20260604`처럼 사용자가 검수한 결과물을 정본화할 때도, 영향을 주는 순간은 해당 내용을 `assets/`·`templates/`·`references/`·`examples/`로 명시적으로 승격했을 때뿐이다.
- Phase 6의 render-audit 계약도 과거 `output/` 전체에 소급 적용하지 않는다. 신규 산출물과 현행 examples 기준선에만 completion 증빙으로 요구한다.
