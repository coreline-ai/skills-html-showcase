## 개발 목적

`youtube_analysis`는 YouTube 영상·채널·댓글·트랜스크립트·챕터 정보를 단순 요약하는 모드가 아니다. 목표는 **시간 기반 영상 콘텐츠를 근거 단위로 해체하고, 사용자가 시청·학습·검증·콘텐츠 제작·재사용 여부를 결정할 수 있는 HTML 리포트**를 생성하는 것이다.

핵심 방향:

- 영상의 핵심 내용을 `TL;DW`로 압축한다.
- 타임스탬프 기반 `Video Evidence Map`으로 주장·근거·시청 가치를 연결한다.
- 댓글/반응은 전체 여론으로 단정하지 않고 주제 클러스터와 반복 질문으로 분리한다.
- 영상 제작자 관점에서는 콘텐츠 갭, 제목/썸네일, 첫 30초 훅, 다음 영상 시리즈까지 제안한다.
- 학습자 관점에서는 볼 구간, 건너뛸 구간, 복습 질문, 실행 체크리스트를 제공한다.
- `FACT / INFERENCE / UNKNOWN`을 분리해 트랜스크립트·댓글·비공개 지표의 한계를 명확히 표시한다.

최종 모드 정의:

```yaml
mode: youtube_analysis
layout_class: .layout-youtube
layout_file: youtube-analysis.html
purpose: YouTube 영상/댓글/트랜스크립트를 시청 판단, 근거 검증, 콘텐츠 기회, 제작 액션으로 변환한다.
primary_vt: timeline
recommended_wg: wg-11, wg-13, wg-14, wg-15, wg-16, wg-18, wg-20
```

## 제외 범위

- 새 `vt-22`, 새 `wg-21`, 새 body-icon 추가 금지. 기존 `vt-` 21종, `wg-` 20종, body-icon 32종을 재사용한다.
- YouTube iframe/player embed 금지.
- 외부/동작 JS 추가 금지. JSON-LD 외 `<script>`는 계속 0.
- YouTube Data API 연동 자동화 구현은 이번 범위에서 제외한다. 사용자가 제공한 URL/메타/트랜스크립트/댓글 또는 브라우징으로 확인 가능한 표면만 사용한다.
- 댓글 전체 크롤러, 자막 다운로드기, 로그인 필요한 YouTube Studio Analytics 자동 수집기는 제외한다.
- 실제 비공개 YouTube Analytics 지표(CTR, retention, revenue, subscribers gain 등)를 추측 생성하지 않는다.
- 장문 transcript 원문 전체 복붙 금지. 필요한 짧은 인용과 요약 중심.
- 기존 historical output 전체 재생성은 별도 범위다. 단, 신규 smoke output은 생성한다.

## `report.html` 예시 분석 반영

사용자 예시 `/Users/hwanchoi/Downloads/report.html`은 “바이브코딩 콘텐츠 갭 리포트” 형태이며 다음 구조를 가진다.

```text
Hero
→ 핵심 통계: 수집 영상 / 댓글 채굴 영상 / 총 댓글 / 신호 댓글
→ 한눈에 보기: 콘텐츠 갭 순위표
→ 콘텐츠 갭 상세: 주제 / 앵글 / 훅 / 근거 댓글 / 대본 초안
→ 다음 액션
```

### 유지할 점

- 조회수가 아니라 반복 질문·불만·댓글 신호에서 콘텐츠 기회를 찾는 관점.
- 상위 후보를 앵커 링크로 빠르게 탐색하는 구조.
- 각 주제를 `앵글 → 훅 → 근거 → 대본 초안`까지 실행 가능하게 연결하는 방식.
- 실제 댓글 근거를 남기는 태도.

### 개선할 점

- 시간 기반 영상 분석이 약하므로 `타임스탬프 챕터 맵`과 `Video Evidence Map`이 필요하다.
- 콘텐츠 기회 판단축을 `수요 강도`, `경쟁 공백`, `제작 난이도`, `시리즈 확장성`으로 분리해야 한다.
- 댓글 근거가 상세 카드 안에 묻히지 않도록 `Comment Signal Wall`을 독립 섹션으로 둔다.
- 제작자가 바로 쓰는 `제목 후보`, `썸네일 문구`, `첫 30초 훅`, `촬영/화면 증거`, `CTA`가 필요하다.
- 현재 독립 CSS 페이지처럼 보이므로 `adaptive-html-final`의 `.layout-*`, `vt-*`, `wg-*`, 3테마 계약 안으로 흡수해야 한다.

- 언어
- 캡션/트랜스크립트 상태
- 댓글 수집 여부
- 메타데이터 출처
- 분석 기준 시각 `observed_at`
- FACT / INFERENCE / UNKNOWN 범례

### 2. TL;DW + Watching Decision

목적: 사용자가 “끝까지 볼지, 특정 구간만 볼지, 요약만으로 충분한지” 결정하게 한다.

필드:

- 핵심 요약 3~5줄
- 추천 시청 대상
- 꼭 볼 구간
- 건너뛰어도 되는 구간
- 확인 필요한 주장
- 최종 판단: `Watch all / Watch sections / Summary enough / Verify first`

### 3. Video Evidence Map

목적: 영상의 주장을 시간·근거·신뢰도와 연결한다.

| 시간 | 장면/주제 | 핵심 주장 | 근거 | 시청 가치 | 신뢰도 | 후속 행동 |
|---|---|---|---|---|---|---|
| `00:00–01:20` | 훅 | 문제 정의 | transcript | 꼭 볼 구간 | FACT | 저장 |
| `04:10–06:30` | 사례 | 방법 제안 | 화면/설명 | 선택 시청 | INFERENCE | 실습 |

규칙:

- timestamp가 없으면 구간 대신 `구간 확인 불가`로 표시한다.
- transcript 기반 문장은 짧게만 인용한다.
- 확인 불가 주장에는 `TODO_CHECK` 또는 `UNKNOWN`을 붙인다.

### 4. Chapter & Retention Story

목적: YouTube의 시간 기반 구조를 HTML에서 읽기 쉽게 만든다.

필드:

- 챕터명
- 시작/종료 시간
- 역할: Hook / Context / Demo / Proof / CTA
- 예상 이탈 지점
- 예상 재시청 지점
- 실제 Analytics 여부

규칙:

- 실제 YouTube Analytics 접근 시 `Intro`, `Spikes`, `Dips`, `Top moments`를 FACT로 표시한다.
- 접근 불가 시 “콘텐츠 구조상 추정”으로 분리한다.

### 5. Comment Signal Wall

목적: 댓글을 전체 여론이 아니라 반복 질문/불만/요청 클러스터로 정리한다.

클러스터 예:

- 반복 질문
- 막힘/불만
- 오해 지점
- 찬반 논쟁
- 후속 영상 요청
- 구매/도입 신호
- 댓글 CTA 후보

규칙:

- 댓글 원문은 짧은 인용만.
- 표본 수와 수집 기준을 표시한다.
- 댓글이 없으면 `댓글 분석 미수행`으로 표시한다.

### 6. Opportunity Matrix

목적: 다음 콘텐츠를 고르게 한다.

축:

```text
Y축: 시청자 수요 강도
X축: 경쟁 공백 / 기존 콘텐츠 포화도
```

분류:

| 영역 | 의미 |
|---|---|
| Make Now | 수요 강하고 경쟁 공백 큼 |
| Validate | 수요는 있으나 근거 부족 |
| Series | 단일 영상보다 시리즈화 적합 |
| Drop | 신호 약하거나 제작 비용 대비 낮음 |

### 7. Claim / Evidence / Risk Matrix

목적: 영상 속 주장을 검증 가능한 형태로 만든다.

필드:

- 주장
- 근거 위치
- 근거 유형: transcript / metadata / comment / external / inference
- 신뢰도
- 확인 필요
- 리스크
- 다음 검증 행동

### 8. Video Blueprint Cards

목적: 상위 기회를 실제 영상 제작안으로 바꾼다.

각 카드:

- 추천 제목 후보 3개
- 썸네일 문구 후보 3개
- 첫 30초 훅
- 챕터 구조
- 반드시 보여줘야 할 화면/증거
- 피해야 할 함정
- 댓글 CTA
- 후속 영상/쇼츠/블로그 아이디어

### 9. Reuse Pack

목적: 분석 결과를 다른 콘텐츠로 재사용한다.

- 블로그 아웃라인
- 쇼츠 5개 아이디어
- 뉴스레터 요약
- 커뮤니티 글
- SEO 키워드
- 댓글 답변 템플릿
- 챕터/Key Moments 후보

### 10. Source Limits

목적: 분석 한계를 명시한다.

- transcript 없음
- 자동 자막 오류 가능
- 댓글 미수집
- 비공개 Analytics 접근 불가
- 조회수/좋아요/댓글 수 변동 가능
- Shorts viewCount 기준 차이 가능
- 스폰서/수익/내부 의도 확인 불가

## 절대 회귀 방지 계약

1. **YouTube embed 금지**
   - `<iframe>`, YouTube player, autoplay, 외부 player JS 금지.
   - 영상은 링크와 메타/근거로만 다룬다.

2. **외부/동작 JS 0 유지**
   - JSON-LD 외 `<script>` 금지.
   - 인터랙션은 `<details>`, `:checked`, `:target`, CSS만.

3. **FACT / INFERENCE / UNKNOWN 분리**
   - FACT: YouTube 페이지/API/제공 transcript/사용자 입력에서 직접 확인.
   - INFERENCE: 관측 사실에서 나온 해석.
   - UNKNOWN: 비공개 통계, 수익, 실제 retention, 스폰서 계약, 삭제된 자막 등.

4. **Transcript/댓글 날조 금지**
   - transcript가 없으면 `확인 불가`.
   - 댓글은 표본일 뿐 전체 여론으로 단정하지 않는다.
   - 긴 transcript 원문 복붙 금지.

5. **변동 지표 기준 시각 필수**
   - 조회수, 좋아요, 댓글 수, 구독자 수는 `observed_at` 표시.

6. **기존 라이브러리만 사용**
   - 새 `wg-21`, 새 `vt-22`, 새 body icon 추가 없이 기존 자산 재사용.

7. **프로파일 계약 유지**
   - `diagram`: vt 마크업만.
   - `widget`: wg 마크업만.
   - `auto`: 둘 다.

8. **레이아웃 안전**
   - semantic `section` 자체에 grid 직접 적용 금지.
   - `.video-signal-grid`, `.video-evidence-grid`, `.chapter-grid`, `.blueprint-grid` 같은 내부 wrapper만 grid 사용.
   - 모든 table은 visible `<caption>` 필수.
   - 모바일 390px overflow 확인.

9. **코어 CSS 해시 리베이스**
   - `theme.css`, `components.css`, `visual-components.css`, `layouts.css`, `print.css` 수정 시 새 코어 해시 생성.
   - 신규 output은 새 `sources/css-integrity.json`과 asset snapshot을 가져야 한다.

## 잔여 리스크 / 후속 과제

- YouTube Data API 자동 수집은 이번 범위가 아니므로, 실제 metadata/comment 자동 수집 스킬은 후속으로 분리할 수 있다.
- YouTube Studio Analytics retention/CTR는 로그인/권한이 필요하므로 일반 공개 분석에서는 UNKNOWN 또는 추정으로만 다뤄야 한다.
- Shorts는 viewCount 기준과 구조가 일반 영상과 다르므로 후속 `youtube_shorts_analysis` 세부 규칙이 필요할 수 있다.
- 여러 영상/채널 단위 분석은 `youtube_channel_analysis` 또는 `content_gap_analysis`로 분리할지 후속 판단이 필요하다.
- transcript가 없는 영상은 분석 품질이 크게 낮아지므로, 사용자에게 transcript 제공을 요청하는 fallback UX가 필요하다.
- 실제 smoke output을 README 갤러리에 올리려면 스크린샷과 GitHub Pages 경로까지 별도 QA가 필요하다.
