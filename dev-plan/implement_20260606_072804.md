## 개발 목적

완성된 editorial HTML을 공유·인쇄·썸네일·외부 배포용으로 변환한다.

- 입력: 자기완결 HTML 산출물 디렉터리
- 출력: PDF / PNG / webp 산출물과 상세 manifest
- 핵심 요구: `:has()` 기반 CSS-only 테마, 인라인 CSS, 대형 SVG, 무 JS 출력물의 시각 충실도 유지
- 최종 방향: **A안 유지 — Node Playwright(Chromium) 렌더 + sharp 기반 webp 파생, 스킬 본체와 분리**

전문가 병렬 검토 결론은 **KEEP with ADJUST**다. Playwright/Chromium과 sharp 선택은 맞지만, PDF 테마 상태 누수, WebP 16383px 한계, 긴 페이지 메모리, dark2 처리, manifest/exit code/HTML 무수정 증명은 계획서에 반드시 보강해야 한다.


권장 옵션:

| 옵션 | 기본값 | 설명 |

| `--scale` | `2` | PNG deviceScaleFactor |
| `--viewport` | `1280x900` | Chromium viewport |
| `--concurrency` | `1` | 페이지 처리 동시성. 최대 2 권장 |
| `--pdf-media` | `print` | `print` 또는 `screen` |
| `--pdf-themes` | 없음 | screen PDF에서만 테마별 PDF 생성 |
| `--pdf-format` | `A4` | PDF paper format |
| `--pdf-margin` | `12mm` | PDF margin shorthand |
| `--webp-quality` | `82` | sharp webp quality |
| `--webp-max-edge` | `16383` | WebP 단일 이미지 최대 긴 변 |
| `--webp-mode` | `downscale` | `downscale` 또는 `chunks` |
| `--show-controls` | `false` | themebar/reading progress를 screenshot에 포함 |
| `--offline` | `false` | 외부 폰트 차단. 폴백 warning 기록 |
| `--strict-fonts` | `false` | 폰트 로딩 실패 시 artifact fail |
| `--require-webp` | `false` | sharp 부재 또는 webp 실패를 hard fail 처리 |

## 변환별 상세 조건

### 1. 페이지 수집

- 수집 대상:
  - `root/*.html`
  - `root/pages/*.html`
- 정렬:
  - `index.html` 우선
  - 나머지는 상대 경로 문자열 정렬
- 제외:
  - `exports/`
  - `_work/`
  - 숨김 디렉터리
  - non-html 파일
- 주의:
  - `output/final_20260604/index-beginner-width.html`처럼 root에 있는 보조 HTML도 반드시 포함한다.

### 2. 렌더 안정화

- `pathToFileURL(absPath).href`로 로드
- `page.goto(url, { waitUntil: 'load' })`
- `page.waitForLoadState('networkidle', { timeout: <short> })`는 best-effort
- `document.fonts.ready` timeout
- `document.images` decode timeout
- `reducedMotion:'reduce'`
- screenshot에는 `animations:'disabled'` 사용
- `animation-play-state:paused` 전역 주입은 기본 금지

### 3. 테마 적용

- DOM 기준 존재 확인:

```js
input[type="radio"][name="ahf-theme"]#ahf-${theme}
```

- 존재하면 runtime에서 checked + input/change 이벤트 dispatch
- 존재하지 않으면 skip
- `dark2`는 정식 스킬 테마가 아니라 **존재 시 캡처하는 opportunistic theme**
- themebar/control은 기본 export에서 숨김:
  - `.ahf-themebar`
  - `.reading-progress`
  - `.skip`
  - `.ahf-color-audit`는 기본 숨김 여부를 옵션화하되, 공유용 산출은 숨김 권장
- `--show-controls`일 때만 표시

### 4. PNG

- 기본: `page.screenshot({ fullPage:true, path, animations:'disabled' })`
- context: `deviceScaleFactor = --scale`
- preflight:
  - `scrollWidth`
  - `scrollHeight`
  - `pixelWidth = scrollWidth * scale`
  - `pixelHeight = scrollHeight * scale`
  - `rawBytes = pixelWidth * pixelHeight * 4`
- raw memory estimate를 manifest와 로그에 기록
- PNG는 원본 master로 보존하고 다운스케일하지 않는다.
- 매우 긴 페이지가 Chromium 한계를 초과하면 artifact fail 또는 향후 `png chunks` 옵션으로 분리한다.

### 5. WebP

- 입력은 반드시 저장된 PNG master 파일.
- sharp 사용:
  - `sharp(pngPath)`
  - 긴 변 > 16383이면 `resize({ width: 16383, height: 16383, fit:'inside', withoutEnlargement:true })`
  - `.webp({ quality: webpQuality, smartSubsample:true })`
- 기본 mode:
  - `full`: 긴 변 ≤ 16383
  - `downscaled`: 긴 변 > 16383
- 선택 mode:
  - `chunks`: 원해상도 보존이 필요한 경우 `part001`, `part002`로 분할
- 단일 원해상도 WebP가 16383px를 초과하면 **REJECT**.

### 6. PDF

- 기본 print PDF:
  - fresh page를 사용하거나 PDF 직전 `#ahf-light` reset
  - `page.emulateMedia({ media:'print' })`
  - `page.pdf({ printBackground:true, preferCSSPageSize:true, format: pdfFormat, margin })`
- `preferCSSPageSize:true`는 유지하되, `print.css`에 `@page`가 없을 수 있으므로 `format/margin` 기본값을 명시한다.
- screen PDF:
  - `page.emulateMedia({ media:'screen' })`
  - theme radio 적용
  - controls 기본 숨김
  - 파일명 `__screen__<theme>.pdf`

### 7. 실패 / exit 정책

- 페이지/테마/포맷 단위 try-catch
- 실패 artifact는 manifest에 `status:'failed'`, `error` 기록
- skip artifact는 `status:'skipped'`, `skipped_reason` 기록
- 최종 exit:
  - pdf/png required artifact 실패 → exit 1
  - sharp 없음으로 webp skip → 기본 exit 0
  - `--require-webp`일 때 webp skip/fail → exit 1
- manifest는 실패가 있어도 항상 작성한다.

## 잔여 리스크 / 후속 과제

- 초장문 PNG 자체가 Chromium 한계에 닿는 경우 `png chunks` 또는 section capture 옵션이 필요할 수 있다.
- WebP chunk 모드는 v1에서 옵션/TODO로 둘 수 있으나, 원해상도 WebP 요구가 생기면 필수화해야 한다.
- CDN 폰트 완전 결정론이 필요하면 후속으로 로컬 폰트 임베드 또는 폰트 캐시 정책을 설계해야 한다.
- `dark2`는 현재 정식 스킬 테마가 아니라 특수 산출물 호환 기능이다. 향후 스킬 테마 계약이 4테마로 바뀌면 export 계획도 재정리해야 한다.
