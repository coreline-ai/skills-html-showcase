## 개발 목적

`manual_analysis`는 기존 매뉴얼을 단순 요약하는 모드가 아니다. 목표는 **PDF/HTML/README/제품 메모/API 스펙/절차 문서/스크린샷 OCR/기존 사용자 가이드**를 입력받아, 독자가 실제로 따라 하고 운영하고 문제를 복구할 수 있는 **역할별 실행형 매뉴얼 HTML**로 재구성하는 것이다.

핵심 방향:

- 매뉴얼을 `Reader Path`, `Task Execution`, `Reference Accuracy`, `Failure Recovery` 관점으로 해체한다.
- 사용자/관리자/개발자/운영자/지원팀 등 역할별 진입 경로를 분리한다.
- 절차는 목표, 사전조건, 단계, 기대 결과, 검증 방법, 실패 시 조치를 함께 제공한다.
- 설정/API/CLI/옵션은 산문이 아니라 표·카드·참조 블록으로 스캔 가능하게 만든다.
- 기존 매뉴얼을 분석할 때는 누락·중복·모순·stale 위험·위험 작업 미표시를 품질 감사로 드러낸다.
- 확인되지 않은 버전/권한/제한/운영 상태는 추측하지 않고 `UNKNOWN` 또는 `확인 필요`로 표시한다.

최종 모드 정의:

```yaml
mode: manual_analysis
layout_class: .layout-manual
layout_file: manual-analysis.html
purpose: 기존 매뉴얼/제품 메모/API 스펙/절차 문서를 분석해 역할별 실행 매뉴얼, 요약본, 운영 가이드, 트러블슈팅 문서로 재구성한다.
primary_vt: hero-map
secondary_vt: checklist-flow, quality-gate, file-tour, process-swimlane, decision-tree, risk-matrix, timeline
recommended_wg: wg-04, wg-13, wg-16, wg-18, wg-11, wg-12, wg-14
```

### 1. Source & Version Snapshot

목적: 매뉴얼의 신뢰 범위와 최신성을 첫 화면에서 고정한다.

필드:

- 제품/문서명
- 버전/에디션/플랫폼
- 입력 출처: PDF/HTML/README/API spec/OCR/메모
- 원문 날짜 또는 추정 날짜
- 분석 기준 시각 `observed_at`
- 대상 독자
- 확인된 사실 / 추론 / 확인 불가 범례

### 2. Reader Role Router

목적: 독자가 자신에게 필요한 경로로 바로 이동하게 한다.

역할 예시:

- End user: 설치, 시작, 핵심 사용법
- Admin: 권한, 조직 설정, 보안, 데이터 관리
- Developer: API, CLI, integration, webhook
- Operator: 모니터링, 백업, 장애 대응, 롤백
- Support: 증상 분류, 에스컬레이션, FAQ

### 3. Manual Scope & Exclusions

목적: 매뉴얼이 다루는 것과 다루지 않는 것을 분리한다.

필드:

- 포함 범위
- 제외 범위
- 적용 조건
- 버전/플랫폼/에디션 제한
- 별도 문서로 보내야 하는 항목

### 4. First Success Path

목적: 초보 독자가 첫 성공까지 도달하는 최소 경로를 제공한다.

필드:

- 예상 소요 시간
- 최소 준비물
- 핵심 5~7단계
- 성공 확인 방법
- 실패 시 첫 진단 항목

### 5. Mental Model

목적: 매뉴얼을 따라 하기 전에 필요한 개념 지도를 제공한다.

필드:

- 핵심 객체/용어
- 관계도
- 데이터 흐름
- 권한/상태 변화
- 흔한 오해

### 6. Prerequisites & Safety Gates

목적: 위험 작업과 준비 조건을 실행 전에 차단한다.

필드:

- 권한/계정/환경
- 백업/롤백 조건
- 비용/데이터/서비스 영향
- 실행 전 확인 체크리스트
- 금지 조건

### 7. Core Task Recipes

목적: 매뉴얼의 핵심 업무를 절차 단위로 재구성한다.

각 recipe 필드:

- 목표
- 사전조건
- 단계
- 기대 결과
- 검증 방법
- 실패 시 조치
- 관련 reference

### 8. Configuration / API / Reference Extract

목적: 설정값·옵션·필드·API·CLI 정보를 빠르게 확인하게 한다.

필드:

- 이름
- 유형
- 기본값
- 허용값
- 필수 여부
- 적용 범위
- 부작용/주의
- 예시

### 9. Decision Guide

목적: 분기 선택을 명확히 한다.

예시 질문:

- UI로 할 것인가, API/CLI로 할 것인가?
- Cloud인가 self-hosted인가?
- 기본 설정인가 고급 설정인가?
- 롤백 가능한 경로인가?

### 10. Troubleshooting Catalog

목적: 실제 실패 상황을 해결 가능한 구조로 만든다.

필드:

- 증상
- 오류 메시지
- 가능한 원인
- 진단 방법
- workaround
- resolution
- 검증 방법
- 에스컬레이션 조건

### 11. Operations Runbook

목적: 운영/장애/정기 작업을 역할과 시간순으로 정리한다.

필드:

- severity
- 담당 역할
- 알림/연락 채널
- 진단 순서
- 완화 조치
- 롤백
- 사후 기록

### 12. Release / Migration Notes

목적: 변경 영향과 업그레이드 위험을 드러낸다.

필드:

- 변경 버전
- breaking change
- deprecated
- migration path
- compatibility
- rollback 가능 여부
- 확인 필요 항목

### 13. Manual Quality Audit

목적: 기존 매뉴얼의 품질 결함을 개선 대상으로 바꾼다.

점검 항목:

- 역할 누락
- 사전조건 누락
- 기대 결과 누락
- 검증 방법 누락
- 오류 대응 누락
- 버전 조건 누락
- 출처 추적 불가
- 오래된 UI/명령어 위험

### 14. Reuse Pack & Next Actions

목적: 생성 결과를 바로 복사해 쓸 수 있게 만든다.

산출:

- 운영 체크리스트
- 사용자용 Quickstart
- 관리자용 절차
- 지원팀 FAQ
- 문서 개선 backlog
- 다음 개정 우선순위

- 긴 표/명령어/절차가 많은 문서 특성상 390px overflow 검증이 중요하다.
