2Actual capabilities from README and src modules

아래 기능은 README의 기능 표와 실제 src/coreline_auth 모듈명·공개 클래스/함수 확인에 근거합니다.

Authentication core

CorelineAuthService는 owner bootstrap, user creation, password login, magic link, email verification, password reset, session issue/verify/logout/revoke, cleanup, audit listing, health check를 제공합니다.

Admin/RBAC safety

CorelineAdminService는 user list, role update, ban/unban, disable/enable, admin password set, user session list/revoke를 다루며 self-demotion·last privileged lockout 계열 보호 로직을 포함합니다.

FastAPI adapters

fastapi_adapter.py와 fastapi_async_adapter.py는 login, magic link, email verification, password reset, logout, me, admin route mount와 dependency helper를 제공합니다.

Secret-safe primitives

security.py는 token generation, SHA-256 hash/compare, email normalization, password hashing/verify, safe return_to policy를 제공합니다. README는 raw session/magic/reset token 비저장 원칙을 명시합니다.

MFA / AAL2

mfa.py는 TOTP secret/code/recovery code 기능을 제공하고, mfa_vault.py는 SQLite/Redis vault 어댑터를 제공합니다. service.py에는 TOTP enrollment, step-up, recovery-code step-up, AAL2 guard가 있습니다.

OAuth/OIDC

social/connectors.py, social/discovery.py, social/verification.py는 provider config, discovery/JWKS, Google/OIDC ID Token verification을 분리합니다. README는 PKCE, nonce, issuer/audience/time-claim 검증 방향을 설명합니다.

WebAuthn / passkey groundwork

webauthn.py는 challenge 생성, registration/assertion response 검증, origin/RP ID validation, signature verification, sign-counter 계열 검증을 포함합니다.

Storage adapters

storage/base.py, storage/sqlite.py, storage/postgres.py, storage/memory.py, async storage contracts가 user/session/login-flow/audit/MFA/recovery-code 저장 책임을 분리합니다.

Operations evidence

ops_readiness.py는 secret-safe readiness output을 생성하고, observability.py는 in-memory/logging/Prometheus text/JSONL security event sink를 제공합니다.

5FAQ

구매자와 개발자가 동시에 묻는 질문에, 확인 가능한 범위로만 답합니다.

Coreline Auth는 CoreMCP 전용인가요?

아닙니다. AGENTS.md와 README는 Coreline Auth를 독립 인증 모듈로 정의하고, 의존 방향을 host app → coreline_auth로 제한합니다.

JWT만 쓰면 더 간단하지 않나요?

일부 API에는 JWT가 적합할 수 있지만, 이 모듈은 browser cookie session, server-side revoke, CSRF, step-up, admin audit 같은 회수 가능한 통제 흐름을 함께 제공합니다.

패스키는 바로 primary auth로 쓸 수 있나요?

webauthn.py에 registration/assertion 검증 groundwork가 있습니다. 다만 primary auth 제품 주장에는 full ceremony, credential lifecycle, 복구 UX, 실제 브라우저/provider smoke evidence가 필요하므로 확인 필요로 둡니다.

버전은 0.5.0-rc2인가요?

README는 0.5.0-rc2를 표시하지만 pyproject.toml은 0.5.0rc1입니다. 릴리스 전 버전 소스 정합성을 확인해야 하며, 이 랜딩은 버전을 확정 주장하지 않습니다.
