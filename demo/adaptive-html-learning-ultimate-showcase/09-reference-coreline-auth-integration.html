Coreline Auth Integration Reference Manual

Coreline Auth를 독립 인증 모듈로 통합할 때 필요한 경계 규칙, 서비스 구성, 세션, RBAC, MFA, OAuth/OIDC, 운영 readiness 레퍼런스입니다.

1Quick reference

통합자는 먼저 “어디에 두고 무엇을 import하지 않을지”를 알아야 합니다.

  • src/coreline_auth는 coremcp.* 또는 apps.api.coremcp.*를 import하지 않습니다.
  • 의존 방향은 항상 CoreMCP → coreline_auth 단방향입니다.
  • password/session/magic-link/reset token 원문은 DB·log·audit에 저장하지 않습니다.
  • password hashing은 검증된 라이브러리를 사용하고 자체 암호 알고리즘을 만들지 않습니다.
  • v0.2 social/OIDC connector는 v0.1 안정화 이후 범위로 관리합니다.

2Architecture boundary

Coreline Auth는 host app의 하위 기능이 아니라 독립 인증 패키지입니다.

CoreMCP / Host App
  └─ imports coreline_auth
       ├─ service.py / async_service.py
       ├─ storage/*
       ├─ fastapi_adapter.py
       ├─ mfa.py / webauthn.py
       └─ social/*

금지: coreline_auth → coremcp import

Adapter 위치

CoreMCP 전용 적용 코드는 CoreMCP adapter에 둡니다. coreline_auth 내부에 host-specific 정책을 넣지 않습니다.

Protocol 우선

Storage, EmailSender, RateLimiter, MfaVault, MetricSink는 protocol/adapter로 갈라 재사용성을 유지합니다.

4Security defaults

secure-by-default는 구현보다 구성 실패를 막는 설계입니다.

DEFAULT SAFE

hash-only secret, Argon2id, HMAC CSRF, session revoke, audit redaction, Redis rate limit, encrypted MFA vault, exact origin 검증을 기본 경로로 둡니다.

FOOTGUN

demo-only weak secret, in-memory vault production, direct OAuth URL 미검증, CSRF optional adapter, role 변경 후 session snapshot 유지, raw template variable 삽입을 차단합니다.

5Pre-production checklist

문서가 아니라 실제 명령과 실패 테스트로 통합 완료를 증명합니다.

make test
make smoke-demo-secure
python -m coreline_auth.ops_readiness --profile production
python - <<'PY'
from pathlib import Path
bad = []
for p in Path('src/coreline_auth').rglob('*.py'):
    s = p.read_text()
    if 'coremcp' in s.lower() or 'apps.api.coremcp' in s:
        bad.append(str(p))
assert not bad, bad
PY
  • 로그아웃 후 기존 session token이 즉시 거부된다.
  • role 변경 후 기존 관리자 세션이 revoke된다.
  • CSRF header 누락 admin POST가 403으로 실패한다.
  • 동일 TOTP code 동시 재사용이 실패한다.
  • magic-link return_to가 same-origin 및 HTML/URL escaped 처리된다.
