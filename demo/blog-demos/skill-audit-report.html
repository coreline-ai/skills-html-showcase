SKILL AUDIT

adaptive-html-blog-writer SKILL.md 감사 리포트

8개 진단 기준으로 SKILL.md와 3개 references, manifest.json을 라인·섹션별로 점검했습니다. 모드 정의 불일치, 트리거 정규화 부재, 출력 경로 불일치, 완료 기준의 검증 가능성을 중심으로 구체적 개선안을 제시합니다.

스킬 목적 요약

adaptive-html-blog-writer는 URL·PDF·텍스트·아이디어 메모 등 다양한 입력을 받아 목적별 한국어 콘텐츠로 변환하는 다중 모드 스킬입니다. 기존 html-for-beginners의 초보자용 HTML 학습 자료 생성을 기반으로, 전문가 리포트 HTML, 공개 아티클, 교육용 HTML, 블로그 원고/SEO/플랫폼 최적화, 그리고 SKILL.md 자체를 분석·개선하는 감사 모드까지 확장한 것이 핵심입니다. 즉 한 스킬 안에 콘텐츠 생산기 + 자기 점검기를 함께 담은 구조입니다.

1현재 구조 분석

SKILL.md 본문 11개 섹션 + frontmatter + 3개 references + manifest의 역할과 응집도를 먼저 파악합니다.

SKILL.md는 frontmatter(1~18행)와 11개 본문 섹션(20~558행)으로 구성됩니다. frontmatter의 description은 트리거 목록과 기본 출력 원칙까지 담고 있어 사실상 스킬 호출 라우터 역할을 합니다. 본문은 Identity → Core Principles → Input Types → Mode Selection → Workflow → Blog Mode → HTML Rendering → Skill Audit → Quality Gates → Output → Completion → Examples 순으로 흐릅니다. 큰 틀에서 "원칙 → 입력 → 모드 선택 → 워크플로우 → 모드별 상세 → 품질 게이트 → 완료 기준"이라는 합리적 골격을 갖췄습니다.

모드는 문서마다 수가 어긋납니다. frontmatter 설명(4~6행)과 manifest.json(5~14행)·Mode Selection 표(87~96행)는 8개 모드를 전제하지만, 본문 0. Identity(28~34행)는 7개만 나열하며 platform_blog가 빠져 있습니다. 이 불일치가 문서 전반의 신뢰도를 떨어뜨리는 1순위 결함입니다.

references 파일의 역할

  • mode-selection.md — Mode Map, 기본 판단 규칙, 다중 모드 결합(Multi-mode Composition), Conflict Resolution. SKILL.md 3절을 보강하지만 우선순위 체인과 충돌 규칙이 다른 논리를 제시(3절 분석 참조).
  • quality-gates.md — Blog/HTML/Skill 3종 체크리스트. SKILL.md 8절과 거의 동일 내용으로 중복이며, 일부 항목이 본문보다 축약돼 있어 둘 중 무엇이 정본인지 불명확합니다.
  • blog-writing-system.md — 블로그 파이프라인, 드래프트 템플릿, SEO/톤/플랫폼 규칙, 100점 품질 점수표. 5절을 확장하는 유일하게 고유한 reference입니다.

manifest.json은 name, version 1.0.0, based_on, 8개 modes 배열, created만 담은 최소 메타입니다. references·assets 파일 목록이나 진입점(entry) 선언이 없어, SKILL.md 9.1절이 가리키는 파일들과 대조·검증할 근거가 manifest 안에 없습니다.

8개 진단 기준(목적·트리거·입출력 검증·워크플로우 순서·금지 규칙·실패 대응·완료 기준·모드 응집도)에 따라 실제 라인 근거로 정리했습니다.

핵심 결함
P0 3건 — 정체성·라우팅·경로의 동시 불일치

모드 개수(0절 vs manifest), 모드 선택 로직(3절 체인 vs reference 결합), 출력 경로(SHARED_STYLE.html vs design-system.md/template.html) 세 곳이 서로 모순됩니다. 이 세 가지는 스킬이 "무엇을 하고, 무엇을 부르고, 무엇을 내놓는지"의 뼈대라, 먼저 정리하지 않으면 나머지 개선이 모래 위에 쌓입니다.

3개선 방향

진단표의 9개 문제를 P0→P2 순으로 묶어, 실행 가능한 권고로 정리합니다.

P0 · 즉시 수정
1) 모드 정의 단일화

모드 배열은 manifest.json을 단일 정본으로 두고, SKILL.md 0절·3절은 manifest를 참조한다고 명시합니다. 0절 Identity에 platform_blog를 추가해 8개로 맞춥니다.

P0 · 즉시 수정
2) 모드 선택 충돌 규칙 통합

SKILL.md 3절의 우선순위 체인과 mode-selection.md의 결합 규칙을 하나의 결정 트리로 합칩니다. "기본은 단일 모드, 사용자가 명시적으로 복합('스킬 분석 후 블로그')을 요청할 때만 결합, 충돌 시 우선순위 체인 적용" 순서로 일원화합니다.

P0 · 즉시 수정
3) 출력 파일 경로 일관성

실제 배포되는 SHARED_STYLE.html을 정식 템플릿 경로로 통일하고, 미배포된 references/design-system.md·assets/template.html 참조는 삭제하거나 파일을 실제로 추가합니다. manifest에 references·assets 목록을 선언해 대조 가능하게 만듭니다.

P1 · 다음 반영

  • 트리거 정규화 — frontmatter 트리거를 "모드 → 키워드 배열" 형태로 구조화하고, 3절 표의 사용자 표현과 동일 출처에서 생성해 1:1 매핑을 보장합니다. platform_blog 트리거(티스토리/벨로그/네이버/워드프레스)를 명시적으로 그 모드에 귀속시킵니다.
  • 실패·불확실성 대응 추가 — 입력별 실패 분기를 Step 2에 추가합니다: URL 접근 실패 → 사용자에게 본문 붙여넣기 요청, PDF 파싱 불가 → 텍스트 입력 요청, 빈/모호한 소스 → 구조 설계 모드로 폴백, 모드 모호 → 1회 확인 질문.
  • 완료 기준 검증 강화 — 10절을 모드별 완료 기준 표로 분리하고, 환경 의존 표현("다운로드할 수 있다")을 산출물 내부에서 확인 가능한 표현("HTML이면 h1 1개·lang=ko 충족", "블로그면 제목 5+·메타·CTA 포함")으로 바꿉니다.

P2 · 정리 단계

  • 품질 게이트 SSOT화 — 체크리스트는 quality-gates.md를 단일 정본으로, SKILL.md 8절은 한 줄 참조로 축소해 중복·미세 차이를 제거합니다.
  • article_html / blog_seo_html / blog_writer 경계 정리 — 세 모드가 SEO HTML 영역에서 겹칩니다. "공개 아티클(article_html) vs 검색 최적화 블로그(blog_seo_html) vs 원고 중심(blog_writer)"의 결정 기준을 한 문장씩 추가합니다.
  • Final Response 분기 — 파일 생성 성공 시에만 다운로드 줄을 출력하고, 본문 출력 시에는 생략합니다.

4확장 가능한 모드

현재 8개 모드는 "생산(7) + 자기 점검(1)" 구조입니다. 응집도를 해치지 않으면서 실제 빈틈을 메우는 모드를 근거와 함께 제안합니다.

제안 1

translate_localize — 한↔영 현지화 모드

현재 모든 산출물이 한국어 고정(1.1절 기본값 language: Korean)입니다. 해외 공개용 아티클·README 수요가 있을 때 톤과 SEO 키워드까지 현지화하는 모드가 필요합니다. 근거: article_html·blog_seo_html이 이미 GitHub Pages를 대상으로 하지만 영어 출력 경로가 없습니다.

제안 2

refresh_update — 기존 글 갱신 모드

입력 타입에 "기존 블로그 초안"(76행)이 있지만, 처음부터 새로 쓰는 흐름만 정의돼 있습니다. 기존 글의 구조를 유지한 채 사실 업데이트·SEO 보강·끊긴 링크 점검만 수행하는 모드가 실무 수요에 맞습니다.

제안 3

series_planner — 연재/시리즈 기획 모드

단일 글 생산에 최적화돼 있어, 하나의 주제를 3~6편 시리즈로 쪼개 각 편의 제목·핵심 메시지·상호 링크를 설계하는 모드가 비어 있습니다. blog_writer의 상위 기획 레이어로 자연스럽게 얹힙니다.

제안 4 (주의)

skill_generate — 신규 SKILL.md 생성 모드

현재 skill_audit는 "기존 스킬 분석·개선"만 다룹니다. 백지에서 새 SKILL.md를 만드는 수요가 있으나, 추가 시 skill_audit와 책임이 겹쳐 응집도가 흔들릴 수 있습니다. 별도 모드보다는 skill_audit의 하위 옵션(audit/scaffold)으로 두는 편을 권합니다.

확장 시 경계
모드 인플레이션 경고

이미 article_html·blog_seo_html·blog_writer가 SEO HTML 영역에서 겹칩니다. 새 모드를 추가하기 전에 기존 모드의 옵션으로 흡수 가능한지 먼저 검토해야 합니다. 모드는 "사용자 의도가 명백히 다를 때"만 늘리는 것이 응집도(기준8)를 지키는 길입니다.
