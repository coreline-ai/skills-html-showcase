OAuth는 로그인 프로토콜이 아닙니다. OIDC가 OAuth 위에 사용자 신원 확인 계층을 얹은 것입니다.

4단계별 흐름

1. Provider 설정 검증: HTTPS, issuer, jwks_uri, no credentials, no fragment
2. 로그인 시작: nonce + OAuthPKCE.create() + begin_social_login()
3. Authorization URL: state + nonce + code_challenge + S256
4. Callback: code + state 수신, nonce/verifier cookie 확인
5. Token exchange: code + code_verifier 제출
6. ID Token 검증: alg, kid, signature, iss, aud, exp, nbf, iat, azp, nonce
decode-only는 인증이 아닙니다

JWT payload를 읽는 것은 검증이 아닙니다. signature, issuer, audience, expiry, nonce가 맞아야 사용자 신원으로 사용할 수 있습니다.

5실습 1 — Authorization URL에 PKCE와 nonce 붙이기

from urllib.parse import urlparse, parse_qs
from coreline_auth import GoogleOAuthConnector, OAuthPKCE
from coreline_auth.security import generate_token

connector = GoogleOAuthConnector.from_credentials(
    client_id="google-client",
    client_secret="google-secret",
    redirect_uri="http://localhost/social/google/callback",
)
nonce = generate_token()
pkce = OAuthPKCE.create()
start = connector.start_authorization(state="state-123", nonce=nonce, pkce=pkce)
query = parse_qs(urlparse(start.authorization_url).query)
assert query["nonce"] == [nonce]
assert query["code_challenge"]
assert query["code_challenge_method"] == ["S256"]
assert start.code_verifier == pkce.code_verifier

7실습 3 — ID Token 검증 규칙 만들기

def verify_id_token(id_token, *, jwks, expected_issuer, expected_audience, expected_nonce):
    header, payload, signature = decode_compact_jwt(id_token)
    if header["alg"] != "RS256":
        raise AuthenticationFailed("invalid alg")
    key = find_jwk_by_kid(jwks, header["kid"])
    verify_rs256_signature(key, id_token)
    if payload["iss"] != expected_issuer:
        raise AuthenticationFailed("issuer mismatch")
    if expected_audience not in as_list(payload["aud"]):
        raise AuthenticationFailed("audience mismatch")
    if payload["exp"] < now():
        raise AuthenticationFailed("expired token")
    if payload.get("nonce") != expected_nonce:
        raise AuthenticationFailed("nonce mismatch")
    return payload

8퀴즈와 정답 해설

  1. state와 nonce의 차이? state는 callback flow 보호, nonce는 ID Token과 인증 요청을 묶습니다.
  2. PKCE가 막는 대표 공격? Authorization code interception입니다.
  3. ID Token decode만 하면 안 되는 이유? signature, issuer, audience, expiry를 보장하지 않기 때문입니다.
  4. code_verifier는 언제 쓰나? token endpoint에서 authorization code를 교환할 때 보냅니다.
  5. JWKS가 필요한 이유? ID Token signature를 검증할 public key를 찾기 위해서입니다.

✓Production Checklist

  • OIDC scope에 openid 포함
  • state, nonce는 고엔트로피 난수
  • PKCE는 S256
  • callback state는 1회 소비
  • token endpoint는 HTTPS only
  • raw token은 log/audit/DB 저장 금지
  • JWKS TTL cache와 kid miss cooldown
  • redirect URI exact match
