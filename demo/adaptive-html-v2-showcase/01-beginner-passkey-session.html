큰 비유: 예전 로그인은 “비밀번호를 말하면 문을 열어주는 경비실”에 가깝다. 패스키는 “내 기기가 현장에서만 작동하는 도장을 찍어 주고, 경비실은 도장 모양만 확인하는 방식”에 가깝다. 경비실에는 비밀 문장이 남지 않는다.

1왜 비밀번호만으로는 부족한가

비밀번호는 사람이 기억하고 입력해야 하므로 재사용, 피싱, 유출에 약하다. 서버가 비밀번호 원문을 저장하지 않더라도, 사용자가 같은 비밀번호를 여러 곳에서 쓰면 한 사이트의 사고가 다른 서비스로 번진다.

초보자 함정

“DB에 해시만 저장하니까 안전하다”는 말은 절반만 맞다. 해시는 유출 후 오프라인 추측 공격 대상이 될 수 있고, 이미 탈취된 세션은 비밀번호 변경 전까지 살아 있을 수 있다.

2패스키를 열쇠 비유로 이해하기

용어 풀이 · 공개키/개인키

개인키는 내 기기 안에만 있는 비밀 도장이고, 공개키는 서버가 보관하는 도장 모양이다. 로그인 때 서버는 “이 문장에 도장을 찍어 봐”라고 요청하고, 기기는 생체인증 뒤 서명만 보낸다.

Coreline Auth의 passkey 데모도 이 흐름을 설명한다. 중요한 점은 서버가 사용자의 생체정보나 개인키를 받지 않는다는 것이다. 그래서 서버 유출 사고의 피해 반경이 작아진다.

좋은 설계

패스키는 피싱 저항성이 높지만, 계정 복구·기기 분실·관리자 권한 변경·세션 폐기 정책과 함께 설계해야 완성된다.

3MFA와 세션은 어디에 붙는가

MFA는 로그인 이후 더 민감한 작업으로 올라갈 때 한 번 더 확인하는 장치다. Coreline Auth 패치에서는 TOTP 재사용 방지, step-up rate limit, 복구코드 엔트로피, MFA vault guardrail이 보강되었다.

상황초보자식 이해보안 체크
비밀번호 변경자물쇠를 바꿈기존 세션도 폐기
MFA step-up금고 앞에서 한 번 더 확인시도 횟수 제한
권한 강등직원 카드 권한 회수이전 세션 권한도 만료

4따라하기

  1. 비밀번호 변경 후 모든 기존 세션이 무효화되는지 테스트한다.
  2. 관리자가 사용자를 강등했을 때 기존 토큰으로 admin API가 실패하는지 확인한다.
  3. MFA 코드를 여러 번 틀렸을 때 rate limit이 걸리는지 확인한다.
  4. 패스키 origin/RP 검증이 정확한 host 기준인지 확인한다.

✓마지막 Try

오늘 하나만 한다면, “비밀번호 변경 후 기존 세션 폐기” 테스트를 자동화하자. 계정 탈취 사고에서 가장 실질적인 피해 축소 장치다.
