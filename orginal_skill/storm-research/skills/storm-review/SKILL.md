# storm-review: 동료 검토 (Peer Review)

> 기본 가정은 **"이 글에는 문제가 있다"**. 통과시키려 하지 말고 결함을 찾는다.
> Stanford STORM 논문이 명시한 두 실패모드 — **source bias transfer**(출처 편향이 글로 전이),
> **over-association**(관련 없는 사실의 부당한 연결) — 를 전담한다.

## 언제

- `/storm-synthesize`로 종합본이 나온 뒤 **최종화 전 반드시**.
- 임의의 리서치 글·보고서의 편향·비약·미인용을 적대적으로 점검하고 싶을 때 (단독 호출).
- `/storm-research` 풀 파이프라인의 4단계(최종 게이트).

## 입력

- **종합본** (`{{SYNTHESIS}}`): 검토 대상 글 (인용 포함이면 더 정밀).

## 실행 (`prompts/4-peer-review.md` 기반) — 6대 점검

1. **출처 편향 전이** — 인용이 한쪽(업계 자기홍보/단일 진영/구자료)으로 치우쳤나? 편향 의존 문장 지목.
2. **부당한 연결** — "A 다음 B"를 "A가 B를 야기"로 비약한 문장 지목.
3. **미인용 주장** — 출처 없이 단언된 사실 문장 전부 지목.
4. **모순 봉합** — 모순 지도의 충돌이 슬그머니 한쪽으로 봉합됐나?
5. **가짜 확실성** — 증거 약한데 단정한 문장.
6. **누락된 반론** — 회의주의자 관점이 희석됐나? 가장 강한 반론이 살아있나?

## 출력

```
## Peer Review: {주제}
### 결함 목록 (각: 위치 인용 + 유형 + 수정 권고 + 심각도)
### 통과 판정: BLOCKER 있으면 "재작업 필요" / 없으면 "조건부 통과 + MINOR 반영"
### 신뢰도 배지: 출처 다양성·인용 충실도·확신 정직성 (상/중/하)
### 검토 후 남는 가장 중요한 미해결 질문 1개
```

## 규칙 (HARD)

- **이 검토를 건너뛰고 최종화 금지.** 논문이 경고한 실패모드는 정확히 여기서 잡힌다.
- **BLOCKER가 하나라도 있으면** `/storm-synthesize`로 되돌려 수정 후 재검토.
- 검토자는 종합 저자와 **다른 입장**을 유지 (가능하면 다른 LLM/페인에서 — storm-research는 회의주의자 영혼이 담당).
