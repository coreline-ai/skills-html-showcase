## ⚠️ 0. 가장 중요한 경고 — 법률 의견이 아니다 (7대 규칙 #6)

> **AI의 특허 분석은 기술·사업 기획을 위한 예비 검토(preliminary review)다.**
> 침해 여부, 무효 가능성, 권리 범위에 관한 **최종 판단은 변리사 또는 특허 전문 변호사의 검토 대상**이다.

- 모든 산출물 첫 페이지에 위 경고문을 고정으로 박는다.
- 위험도 "중간/높음" 특허는 반드시 `변리사 검토 필요`로 표시(PRD §11.6 8단계, §29).
- "침해한다 / 침해하지 않는다"는 단정을 쓰지 않는다. "겹칠 가능성", "검토 필요"로 쓴다.
- 제목·초록만으로 권리 범위를 판단하지 않는다(§11.5). 반드시 **독립 청구항 원문**까지 본다.

## 1. 분석 목적 — 답해야 할 7개 질문 (PRD §11.1)

특허 분석은 "유사 특허가 있는가"에서 끝나지 않는다. 아래 7개에 답해야 완료다.

1. 어떤 기술 영역에서 특허가 집중되고 있는가? (랜드스케이프)
2. 주요 권리자는 누구인가?
3. 현재 권리가 유효한 특허는 무엇인가? (법적 상태·존속기간)
4. 실제 청구항이 보호하는 범위는 무엇인가? (청구항 분해)
5. 사용자의 제품과 겹칠 가능성이 있는 요소는 무엇인가? (claim-chart)
6. 회피 설계가 가능한가?
7. 사용자가 출원할 수 있는 권리화 지점은 무엇인가? (기회 분석)

→ 1·2는 `patent-landscape`, 3은 `patent-list`/`patent-family-map`, 4·5는 `claim-chart`, 5·6은 `patent-risk-map`/`preliminary-fto-report`, 7은 `patent-opportunity`로 답한다.

## 2. 검색 범위 (PRD §11.2)

| 범위 | 확인 항목 |

| 양도·권리 변동 | 권리자 변경 이력 |

| DB | 범위 | 비고 |
|---|---|---|
| **KIPRIS** (kipris.or.kr) | 국내 특허·실용·디자인·상표 | 한국 특허청 무료 공개 검색 |
| **Google Patents** (patents.google.com) | 글로벌, 영문 기계번역 | 패밀리·인용·법적상태 한눈에, 무료 |

- 위 무료 공개 DB를 우선 사용한다. 유료/로그인 DB는 우회하지 않는다(PRD §3.2).

## 4. 검색 전략 — 키워드만으로는 부족 (PRD §11.3)

다음을 조합한다. 키워드 단독 검색은 누락이 크다.

- 한글·영문 키워드 + 기술 동의어
- 제품 기능 / 해결 문제 표현
- **CPC·IPC 분류코드** (핵심 기술의 분류를 먼저 찾아 분류 기반 검색)
- 주요 출원인 (경쟁사·대기업·대학)
- 주요 발명자
- 인용 특허 (핵심 특허의 인용·피인용 따라가기)
- 유사 청구항 표현
- 특허 패밀리 (한 건 찾으면 패밀리 전체로 확장)

> 검색 절차: ① 키워드로 핵심 특허 1~2건 발견 → ② 그 특허의 CPC/IPC·출원인·인용 확인 → ③ 분류·출원인·인용으로 확장 검색 → ④ 패밀리로 해외 출원 묶기. 사용한 검색식을 모두 저장한다(재현성).

## 5. 특허별 분석 16개 항목 → patent-list.xlsx 컬럼 (PRD §11.4)

각 특허 1건 = `patent-list.xlsx` 1행. 16개 컬럼 모두 채운다(미확인은 빈칸 대신 "미확인").

| 컬럼 | 내용 |
|---|---|
| `patent_number` | 공개번호·등록번호 |
| `jurisdiction` | 출원 국가 |
| `applicant` | 최초 출원인 |
| `current_assignee` | 현재 권리자 (권리 변동 반영) |
| `inventor` | 주요 발명자 |
| `filing_date` | 출원일 (우선일 포함) |
| `legal_status` | 심사 중·등록·소멸·거절·취하 |
| `term_expiry` | 존속기간 (예상 만료일) |
| `patent_family` | 동일 발명의 해외 출원 |
| `independent_claim` | 핵심 권리 범위 (독립 청구항 요약) |
| `dependent_claim` | 세부 구성 (종속 청구항) |
| `key_elements` | 청구항 요소 분해 (A+B+C…) |
| `similarity` | 사용자 기술과 비교 (높음/부분/낮음) |
| `risk_level` | 낮음·중간·높음 |
| `design_around` | 회피(설계 변경) 가능성 |
| `business_impact` | 제품·시장 진입에 미치는 영향 |
| `source_id` | source-index.xlsx 연결 ID |

## 6. 청구항 분석 — 제목·초록 금지, 독립 청구항 분해 (PRD §11.5)

핵심 권리 범위는 **독립 청구항**에 있다. 독립 청구항을 구성요소로 분해한다.

```text
독립 청구항 = 요소 A
            + 요소 B
            + 요소 C
            + 요소 간 결합 관계
```

특허법 원칙(예비 검토 수준): 청구항의 **모든 요소가 사용자 제품에 존재해야** 문언 침해 가능성이 생긴다(All-Elements Rule). 한 요소라도 빠지면 겹침 가능성이 낮아진다 — 이 점이 회피 설계의 핵심이다.

### claim-chart 형식 (`claim-chart.xlsx`)

특허별로 독립 청구항 요소를 행으로 펼치고 사용자 제품과 대조한다(PRD §11.5 표).

| 청구항 요소 | 사용자 제품 | 일치 여부 | 비고 |
|---|---|---|---|
| 문서 입력 모듈 | 있음 | 일치 가능 | 입력 형태 확인 필요 |
| 의미 분석 엔진 | 있음 | 부분 일치 | 구현 방식 다름 |
| 장면 자동 생성 | 있음 | 일치 가능 | 청구항 해석 필요 |
| 영상 렌더링 | 외부 도구 사용 | 부분 일치 | 직접 수행 여부 확인 |

- 일치 여부: `일치 가능 / 부분 일치 / 불일치`. 단정(`침해`)은 쓰지 않는다.
- **하나라도 "불일치"인 요소가 있으면** 그 특허는 회피 가능성이 높다(All-Elements 미충족) → `design_around` 갱신.
- 청구항 해석이 갈리는 부분은 "청구항 해석 필요 — 변리사 검토" 표시.

## 7. FTO 예비 분석 8단계 (PRD §11.6)

Freedom to Operate = 우리 제품을 자유롭게 사업화할 수 있는가의 예비 검토.

1. 제품을 **핵심 기능 단위로 분해**한다.
2. 기능별 관련 특허를 찾는다.
3. **유효한 권리인지 확인**한다 (법적 상태·존속기간 — 소멸·거절·취하 특허는 권리 없음).
4. 독립 청구항을 요소별로 분해한다 (§6).
5. 사용자 제품과 비교한다 (claim-chart).
6. **위험 특허를 분류**한다 (낮음/중간/높음).
7. 회피 설계 가능성을 제시한다.
8. **변리사 검토가 필요한 특허를 표시**한다.

> 8단계 모두 거친 뒤 `preliminary-fto-report.docx`를 쓴다. 첫 페이지 경고문(§0) 필수. "예비 검토"임을 제목과 본문 모두에 명시.

## 8. 권리화 기회 분석 (PRD §11.7)

방어(회피)만이 아니라 **사용자가 출원할 수 있는 지점**도 찾는다. 기존 특허에서 다루지 않은 빈틈:

- 기존 특허에서 다루지 않은 문제
- 새로운 구성요소 조합
- 업무 프로세스
- 데이터 처리 방식
- 사용자 상호작용
- 도메인 특화 알고리즘
- 시스템 통합 구조
- 성능 향상 방식
- 자동화 방법

→ `patent-opportunity.md`에 "출원 후보 아이디어 + 근거(어느 특허도 안 다룸) + 신규성/진보성 예비 판단(변리사 확인 필요)"로 정리. 이것은 사업계획서의 기술 차별성·IP 전략 근거가 된다.
