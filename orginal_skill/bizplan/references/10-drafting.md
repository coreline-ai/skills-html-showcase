# 10 — 사업계획서 초안 작성 프로토콜

> 진입 조건: `business-core.yaml` 확정(Gate 3·4 통과) + `06-template-design/`의 서식 매핑 완료.
> 산출물: `08-draft/<section>.md` (목차 항목별) → `08-draft/business-plan-draft.docx` 통합.
> 이 문서는 SKILL.md 16~17단계의 실행 프로토콜이다. PRD §17 기반.

초안은 "글짓기"가 아니다. **평가자가 확인하려는 질문에 한 문장으로 답하고, 그 답을 근거로 떠받치는 것**이다. 모든 문장은 `business-core.yaml`에서 파생하며, 새 사실·수치를 여기서 만들어내지 않는다(7대 절대 규칙 #1, #4).

---

## 0. 디테일 원칙 — 이 스킬의 핵심 (먼저 읽는다)

> **선정작과 탈락작을 가르는 것은 "글솜씨"가 아니라 "디테일의 밀도"다.** 같은 사업이라도 선정작은 주장마다 근거가 붙고, 추상어가 수치로 치환되며, 의심 지점마다 부록 번호가 박혀 있다. 탈락작은 그럴듯한 문장과 빈 칸뿐이다. (improvement-research §C)

**"디테일"은 분량 늘리기가 아니다.** filler 문장·미사여구로 페이지를 채우는 것은 오히려 감점이다. 디테일 = 아래 4가지의 밀도다.

| 원칙 | 의미 | 적용 |
|---|---|---|
| **D1. 주장 1 : 근거 1 대응** | 모든 핵심 주장에 그것을 떠받치는 근거가 **하나씩** 붙는다. 근거 총 6~10개면 충분 — 개수보다 **연결성**이다. 주장만 있고 근거 없는 문장 = 즉시 보강 또는 삭제. | 한 문단 = 1 주장 + 그 주장의 근거. 근거가 없으면 `[확인 필요]`로 정직하게 표시. |
| **D2. 추상어 → 정량 수치** | "효율적/혁신적/많은/대폭/우수한"은 그 자체로 정보량 0. 반드시 숫자·조건·비교로 치환한다(§2.5 치환 사전). | "효율적" → "처리 시간 8시간→1시간(87.5% 단축, financial-model.xlsx L12, [목표])". |
| **D3. 측정기준·출처·조회일 명시** | 모든 수치는 **무엇을 어떻게 쟀는지(측정기준) + 누가 발표했는지(출처) + 언제 확인했는지(조회일)**가 따라붙는다. 30초 안에 평가자가 검증 가능해야 한다. (improvement-research §E 인용 황금률) | "국내 OO 시장 1.2조원 (출처: KOSIS 검색어 'OO', 2024 기준 / 조회일 2026-06-15 / 본문 2.2절, source-index #14)". |
| **D4. 의심 지점마다 부록 번호** | 평가자가 "정말?"이라고 의심할 만한 모든 지점(성능 주장·시장 규모·매출 추정·경쟁 비교)에 **부록 N / source-index #N**을 박아 즉시 검증 경로를 연다. | "유사 사례 미확인(부록 7 선행조사 결과 참조)". |

### 선정작 vs 탈락작 패턴 (improvement-research §C)

| | 선정작 | 탈락작 |
|---|---|---|
| 문제 정의 | 현장 증거 N개(인터뷰 N명 만족도·사진·사전예약·전환 데이터)로 **정량 입증** | "많은 기업이 어려움을 겪는다" (무근거 일반론) |
| 해결책 | 아이디어가 아닌 **실행 흔적**(언어 선정·외주 견적·설계 완료·MVP 운영 데이터) | "혁신적 AI로 해결" (구상 단계에 머묾) |
| 시장 규모 | 출처·조회일 있는 TAM/SAM/SOM, **보수적 SOM** | 무출처 시장 규모, TAM만 과장 |
| 경쟁 분석 | 5~10개 비교표 + 측정기준 컬럼 + 포지셔닝맵 | 경쟁사 1~2개 나열, "우리가 더 우수" |
| 수익 모델 | 1문장 BM + 단위경제성(LTV/CAC) | 모호한 수익 구조 |
| 매출 추정 | bottom-up·근거 있는 가정 | 과도 추정(시장의 X% 차지) |

> **탈락 공통 결함 6종(improvement-research §C)**: ① 시장 규모 무출처 ② 경쟁 비교 부족 ③ 수익 모델 모호 ④ 매출 과도 추정 ⑤ 예산 불명확 ⑥ 구상 단계 머묾. 초안의 모든 섹션은 이 6종 중 하나라도 해당하면 미완성이다.

## 1. 섹션 작성 7단계 (모든 목차 항목에 동일 적용)

각 섹션을 `08-draft/<section>.md`로 쓸 때 아래 순서를 **건너뛰지 않는다**. 순서가 곧 논리다.

| 단계 | 행동 | 산출 | 자가 점검 질문 |
|---|---|---|---|
| 1 | **평가자 질문 정의** | `evaluator_question` 1줄 | 이 섹션에서 평가자가 진짜 알고 싶은 게 뭔가? |
| 2 | **한 문장 핵심 답변** | `key_message` 1문장 | 이 한 문장만 읽고 다음 섹션으로 넘어가도 손해 없는가? |
| 3 | **근거 배치** | `supporting_claims[]` + 증거 태그 | 각 주장은 `source-index.xlsx`/`evidence-ledger.xlsx` 몇 번 행인가? |
| 4 | **표·그래프·다이어그램 선택** | 시각자료 1~2개 결정 | 이 메시지는 표가 빠른가, 그림이 빠른가, 문장이 빠른가? |
| 5 | **상세 설명 작성** | 본문 단락 | 한 문단 = 한 주장인가? 추상어 뒤에 구체가 붙었는가? |
| 6 | **다음 항목 논리 연결** | 연결 1문장 | 문제→해결→기술→시장→실행 사슬에서 이 섹션은 어디인가? |
| 7 | **출처·수치 확인** | 태그·행번호 대조 | 출처 없는 핵심 통계가 있는가? 다른 섹션과 숫자가 다른가? |

### 섹션 작성 YAML 골격 (PRD §17.1 — `08-draft/<section>.md` 상단 frontmatter로 권장)

```yaml
section:
  official_title:      # 공식 서식의 목차 제목 그대로 (template-map.yaml에서)
  evaluator_question:  # 1단계
  key_message:         # 2단계, 한 문장
  supporting_claims:   # 3단계, 각 항목에 증거 태그 + 행번호
  evidence:            # source-index/evidence-ledger 행 참조
  text:                # 5단계 본문
  tables:              # 4단계 선택 결과
  charts:
  diagrams:
  images:
  source_notes:        # 7단계
  missing_items:       # [확인 필요]로 남은 항목
```

> 2단계의 한 문장 답변은 본문 **맨 앞**에 굵게 둔다. 평가자가 한 섹션을 펼쳤을 때 가장 먼저 보이는 줄이 핵심 답변이어야 한다.

## 2. 기본 표현 원칙 8개

작성 중 항상 위에 두는 표현 규칙. PRD §17.3을 실행 체크리스트로 푼 것이다.

1. **서술식 / 기술식(技術式)을 구분한다.** 서술식 = 흐르는 문장, 기술식 = 항목·표·수식. 한 섹션 안에서도 부분별로 달라진다.
2. **상위 개요는 서술식.** "왜 이 사업인가" 같은 큰 그림은 2~4문장 서술로. 표로 쪼개면 맥락이 끊긴다.
3. **세부 계획은 항목식·표.** 기능 목록, 일정, 예산, 역할은 표·번호목록으로. 산문으로 풀면 평가자가 항목을 못 센다.
4. **한 문단에 하나의 주장.** 한 문단이 두 가지를 말하면 둘 다 흐려진다. 주장이 둘이면 문단을 나눈다.
5. **추상어 뒤에 구체를 붙인다.** "효율적이다" → "처리 시간을 8시간에서 1시간으로 줄인다([목표], financial-model.xlsx 가정 L12)". 모호어는 인터뷰 단계의 적이자 초안 단계의 적이다.
6. **표·그림에는 제목·단위·기준일·출처를 단다.** 4요소가 빠진 시각자료는 미완성이다. 예: `표 3. 국내 OO 시장 규모 추이 (단위: 억원, 기준: 2024.12, 출처: 통계청 KOSIS, source-index #14)`.
7. **강조는 굵게 + 제한된 밑줄.** 핵심 답변 문장·핵심 수치만. 한 페이지에 굵은 글씨가 5곳을 넘으면 강조가 무의미해진다.
8. **화려한 장식 금지.** 이모지, 과도한 색, 그림자, 풀스크린 배경. 평가자는 장식이 아니라 논리를 읽는다. 흑백 출력에서도 같은 메시지가 전달되어야 한다.

### 2.5 추상어 → 구체 치환 사전 (모호어 가드와 연결)

> 인터뷰 단계의 모호어 가드(SKILL.md 5단계)가 초안에서 부활하는 것을 막는다. 아래 단어를 초안에서 발견하면 **그 자리에서 우측 형식으로 치환**한다. 치환할 수치가 없으면 `[확인 필요]`.

| 모호어 (❌) | 치환 형식 (✅) | 예시 |
|---|---|---|
| 효율적이다 / 효율 향상 | 「대상 지표」를 「X→Y」로 「Z%」 개선 (조건·출처·태그) | "검사 시간을 12분→3분으로 75% 단축 (OO조합 8개사 현장 측정, [목표])" |
| 혁신적이다 | 기존 방식 대비 「구조적으로 다른 점」 1문장 + 정량 차이 | "기존 육안검사와 달리 라인 정지 없이 실시간 검출, 검출률 0.84→0.91" |
| 많은 / 대다수 / 상당수 | 정확한 수·비율 + 모집단 + 출처 | "종업원 50인 미만 금속가공 업체 1,240개사 중 78% (KOSIS 2024, 조회일 2026-06-15)" |
| 대폭 / 크게 / 현저히 | 정량 변화폭 (절대값 또는 %) | "대폭 절감 → 연 8,400만원 절감 (인건비 2명분, financial-model.xlsx L22)" |
| 우수한 / 뛰어난 / 높은 성능 | 측정 지표 + 비교 대상 + 조건 | "F1 0.91 (OO-Bench v2 1만장, 공개 베이스라인 0.84 대비 +0.07)" |
| 글로벌 / 세계적 | 대상 국가·시장 명시 + 규모 | "북미·EU 양산차 부품 검사 시장 (TAM 3.2조원, MarketsandMarkets 2025)" |
| AI 활용 / AI 기반 | 어떤 AI 기술이 무엇을 어떻게 | "CNN 기반 표면결함 분할(segmentation) 모델로 미세 크랙 검출" |
| 저렴한 / 합리적 가격 | 가격 숫자 + 비교 기준 | "월 39만원 (경쟁사 비전검사 솔루션 월 평균 120만원의 1/3)" |
| 빠른 시일 내 / 신속히 | 구체 시기 (분기·월) | "2027년 2분기 양산 적용 (추진일정 M14)" |
| 다양한 / 여러 가지 | 항목을 직접 나열 (개수 명시) | "3개 업종(금속가공·사출·표면처리)에 적용" |

> 치환 후에도 모호어 잔존 0이 §5 섹션 완성 체크의 조건이다.

## 3. 작성 방식 — `08-draft/<section>.md` → `business-plan-draft.docx`

- **목차 항목당 파일 1개.** `06-template-design/section-outline.md`의 각 항목을 `08-draft/`에 별도 `.md`로 쓴다. 파일명은 목차 순서를 보존하도록 번호 접두(예: `01-problem.md`, `02-solution.md`).
- **각 섹션은 단독으로 완결.** 다른 섹션을 안 봐도 그 섹션만으로 평가자 질문에 답이 되어야 한다(단, 6단계 연결 문장으로 흐름을 잇는다).
- **시각자료는 경로 참조.** 표는 마크다운 표로 직접, 그림은 `07-diagrams/images/<name>.png` 경로를 `![제목](...)`으로 삽입. 원본 명세는 `diagram-source/`에 보존(7대 규칙·재현성).
- **통합 변환.** 모든 `<section>.md`가 준비되면 목차 순서대로 묶어 `python3 scripts/md_to_docx.py`로 `08-draft/business-plan-draft.docx` 생성. 서식 제약(폰트·여백·분량)은 `06-template-design/template-structure.yaml`을 따른다.
- **수치는 코어에서만.** 초안에 등장하는 모든 수치는 `business-core.yaml` → `evidence-ledger.xlsx`로 추적 가능해야 한다. 초안에서 새 숫자를 즉흥 생성하지 않는다(7대 규칙 #1).

```text
08-draft/
├── 01-problem.md          # frontmatter(section:) + 본문
├── 02-solution.md
├── ...
└── business-plan-draft.docx   # 위 md들을 목차 순서대로 통합
```

## 4. 항목별 최소 디테일·분량 기준 (★ 강화 핵심)

> **각 섹션은 아래 "최소 요소"를 전부 담아야 초안 완료다.** 하나라도 빠지면 그 섹션은 미완성으로 두고 `missing_items`에 사유를 적는다. PSST/R&D 표준 목차(improvement-research §A)와 1:1 매핑된다.
>
> **글보다 표·도식을 우선한다.** 같은 정보를 문장으로 풀면 평가자가 항목을 못 세고, 표로 주면 한눈에 검증한다. 세부 계획(기능·일정·예산·역할·비교)은 **원칙적으로 표**로.

### 4.0 문서 전체 필수 시각화 5종 (improvement-research §A·F)

| 시각화 | 용도 | 산출 위치 | 비고 |
|---|---|---|---|
| **시장 규모** (TAM/SAM/SOM 동심원 또는 막대) | 시장성 입증 | `07-diagrams/images/` + `market-sizing.xlsx` 캡처 | bottom-up SOM 강조 |
| **개발 단계** (As-Is → To-Be, TRL, MVP 구성도) | 실현가능성 | 다이어그램 | 실행 흔적 시각화 |
| **추진 로드맵** (간트 차트) | 추진일정 | 다이어그램 + 표 | 분기·월 단위 마일스톤 |
| **팀 구성** (조직도 / 역량 매트릭스) | 팀 | 다이어그램 + 표 | R&R·경력 명시 |
| **자금 운용** (사업비 명세·재원 비중) | 예산 | `financial-model.xlsx` 캡처 | 직접비/간접비 블록 |

> 시각자료가 5종 미만이면 "표·도식 비중 부족"으로 디테일 감점 가능. 단, 공고 페이지 제한 내에서 운용(§6).

### 4.1 문제 정의 / 배경·필요성 (Problem)

평가자 질문: **"어떤 고객의 어떤 문제가, 얼마나 심각한가?"**

| 최소 요소 | 기준 |
|---|---|
| 고객 세그먼트 정의 | 누구인지 정량 특정 (규모·수·업종) |
| **현장 증거 N개** | 인터뷰 N명·만족도·사진·사전예약·전환 데이터 중 **최소 2개**, 출처·조회일 |
| **정량 페인포인트** | 문제의 크기를 숫자로 (시간·비용·불량률·손실액) |
| As-Is / To-Be 대비 | 현재 상태 vs 목표 상태 표 또는 도식 |
| Why now | 정책·기술·소비 트렌드 변화 연결 (improvement-research §C) |

표/도식 권장: As-Is/To-Be 비교표, 페인포인트 정량 막대, 현장 사진.

### 4.2 해결책 / 실현가능성 (Solution)

평가자 질문: **"정말 만들 수 있는가? 지금 어디까지 했는가?"**

| 최소 요소 | 기준 |
|---|---|
| 해결 원리 1문장 | 문제와 1:1 대응 |
| **실행 흔적** | 아이디어가 아닌 증거 — 언어 선정·외주 견적·설계 완료·MVP 운영 데이터·PoC 결과 중 최소 1개 |
| 준비 정도(현황) | MVP 표·흐름도·구성도 (PSST 2-1) |
| 기술 차별성 | 경쟁 대비 **구조적** 차이 + 정량 비교 (조건 명시) |
| 개발 단계 | TRL 또는 단계별 완료 상태 |

표/도식 권장: 시스템 구성도, MVP 기능 표, 개발 단계 로드맵.

### 4.3 시장 분석 (Market)

평가자 질문: **"이 시장은 얼마나 크고, 우리가 가져올 수 있는 몫은 얼마인가?"**

| 최소 요소 | 기준 |
|---|---|
| **TAM** (top-down) | 공신력 기관 전체 시장 × 조건 비율 축소, **출처·조회일** (improvement-research §F) |
| **SAM** | `SAM = TAM × 필터%`, 필터 근거 명시 |
| **SOM** (bottom-up·필수) | `잠재고객수 × ARPA` = "3년 내 실제 가져올 돈". **보수적 추정이 신뢰↑** |
| 성장률·CAGR | 출처 있는 연평균 성장률 |
| 시장 세분화 | 타깃 세그먼트 우선순위 |

> **흔한 실수(improvement-research §F)**: TAM 과장 + SOM 구체성 부족 = 감점. SOM이 핵심이다.
> 무출처 시장 규모는 탈락 공통 결함 #1. 모든 시장 수치에 출처·조회일·source-index 행번호.

표/도식 필수: TAM/SAM/SOM 동심원 또는 막대, `market-sizing.xlsx` 산정표.

### 4.4 경쟁 분석 (별도 §5에서 상세) — 최소 요소

| 최소 요소 | 기준 |
|---|---|
| 경쟁사 5~10개 | 직접/간접/잠재 3분류 |
| 비교표 | **"측정기준+근거" 컬럼 필수** |
| 포지셔닝맵 | 2축 → 빈 공간 = 차별점 |
| SWOT | 강점·약점·기회·위협 |
| 차별성 | "왜 우리가 더" + 구조적 이유 + 진입장벽 |

### 4.5 수익 모델 / BM (Business Model)

평가자 질문: **"어떻게 돈을 버는가? 단위경제가 성립하는가?"**

| 최소 요소 | 기준 |
|---|---|
| BM 1문장 | 누가·무엇을·얼마에 (PSST 3-1) |
| 가격 구조 | 단가·과금 방식 + 경쟁 대비 근거 |
| **단위경제성** | `LTV = ARPA×GM%/Churn`, `CAC = (영업+마케팅)/신규고객`, `LTV/CAC ≥ 3` |
| 매출 추정 | bottom-up: `매출 = 가격 × 수량` 또는 `MAU × 전환율 × 객단가` |

> 모호한 수익 구조·과도 매출 추정은 탈락 결함 #3·#4. bottom-up·보수적 추정.

### 4.6 추진 전략 / 일정 / 자금 (Scale-up)

|---|---|

| **추진일정 (간트)** | 분기·월 단위 마일스톤 매트릭스 |

| 정량 목표 | §6 공식으로 (활동→결과→숫자) |

## 5. 경쟁 분석 작성법 (★ 강화 — improvement-research §D)

> 경쟁 분석 부족은 탈락 공통 결함 #2다. "우리가 더 우수하다"는 주장만 있고 비교표·포지셔닝이 없으면 즉시 탈락권. 아래 4구성을 **모두** 채운다.

### 5.1 경쟁사 5~10개 — 3분류

| 분류 | 정의 | 예 |
|---|---|---|
| **직접 경쟁** | 같은 고객의 같은 문제를 같은 방식으로 푸는 곳 | 동종 솔루션 업체 |
| **간접 경쟁** | 같은 문제를 다른 방식으로 푸는 곳 | 외주 검사 대행, 수기 검사 인력 |
| **잠재 경쟁** | 지금은 아니지만 진입 가능한 곳 | 대기업 비전 사업부, 해외 진입 후보 |

> 직접 경쟁만 나열하면 "시장을 좁게 본다"는 인상. 간접·잠재까지 짚어야 시장 이해도를 입증한다.

### 5.2 비교표 — "측정기준 + 근거" 컬럼 필수 (공정성)

> 단순히 항목에 ○/× 또는 점수를 박으면 "자기에게 유리하게 짰다"는 의심을 받는다. **각 비교 항목이 무엇을 어떻게 측정했고, 그 근거가 어디인지**를 컬럼으로 명시해 공정성을 입증한다.

**비교표 골격 (마크다운):**

```markdown
| 비교 항목 | 측정기준 | 본 사업 | 경쟁사 A | 경쟁사 B | 근거 |
|---|---|---|---|---|---|
| 검출 정확도 | F1, OO-Bench v2 1만장 동일조건 | 0.91 | 0.84 | 0.79 | benchmark-comparison.xlsx, #22 |
| 처리 속도 | 1장당 ms, 동일 GPU | 18ms | 45ms | 30ms | 자체측정, [추정], #23 |
| 가격 | 월 구독료(원), 공식가 | 39만 | 120만 | 80만 | 각사 공식 홈페이지, 조회일 2026-06-15 |
| 도입 난이도 | 셋업 소요일 | 1일 | 7일 | 3일 | 고객 인터뷰, [추정], #24 |
```

- 핵심 비교 항목 **3~5개**(가격·기능·점유율·만족도·성능 등). 너무 많으면 초점이 흐려진다.
- 모든 셀에 측정기준이 동일하게 적용됐는지 확인(사과 vs 오렌지 비교 금지, 7대 규칙 #6).
- 자사에 불리한 항목도 정직하게 표기 → 오히려 신뢰도 상승.

### 5.3 포지셔닝맵 (2축 → 빈 공간 = 차별점)

- X·Y 두 속성 축을 고른다(예: 가격 ↔ 정확도, 범용성 ↔ 전문성). 마케팅 메시지가 아니라 **고객이 실제로 비교하는 축**으로.
- 경쟁사를 좌표에 배치 → **비어 있는 사분면**이 우리의 포지션이자 차별점.
- 다이어그램으로 `07-diagrams/`에 그린다. 자사가 빈 공간에 있고 그 공간에 고객 수요가 있음을 1문장으로 설명.

### 5.4 SWOT

| | 도움 (Helpful) | 방해 (Harmful) |
|---|---|---|
| **내부** | Strengths (강점) | Weaknesses (약점) |
| **외부** | Opportunities (기회) | Threats (위협) |

> 약점·위협을 비워두면 "자기 인식 부족"으로 본다. 약점에는 대응책을 1줄씩 붙인다.

### 5.5 차별성 = "왜 우리가 더" + 구조적 이유 + 진입장벽

차별성은 "우리가 더 잘한다"가 아니라 **세 겹**으로 쓴다 (improvement-research §D):

1. **왜 우리가 더 나은가** — 정량 비교(§5.2 표)로 입증.
2. **경쟁사가 못 하는 구조적 이유** — 단순히 "우리가 노력한다"가 아니라, 경쟁사의 사업 모델·기술 스택·고객 구조상 따라오기 어려운 이유. 예: "경쟁사 A는 범용 클라우드 SaaS라 현장 폐쇄망 요구를 수용 못 함."
3. **진입장벽** — 우리가 선점한 뒤 후발주자를 막는 해자(데이터·특허·전환비용·네트워크 효과·규제 인증).

## 6. 정량/정성 목표 작성 공식 (★ 강화 — improvement-research §B)

> 평가위원이 가장 먼저 트집 잡는 지점이 목표 진술이다. 아래 공식을 벗어난 목표는 "근거 없는 희망"으로 간주된다.

### 6.1 정량 목표 공식

```
정량 목표 = 활동 → 직접 결과 → 숫자
          + (조건·환경 + 측정방법 + 달성시기)
          + 세계최고수준 보유국·수준 비교근거
```

- **숫자부터 쓰지 말 것.** "○○ 활동을 통해 △△백만원" 순서. 활동과 결과의 인과가 보여야 한다.
- 숫자에는 **출처**(계약 건수, 국내/해외 분리).
- 지표에는 **조건·환경 + 측정방법 + 달성시기 + 비교근거** 결합.

**예시 (improvement-research §B):**

> ✅ "이온풍 비행기 평균 이동거리 **≥100m** (무풍 실내, 0.5m 높이, 10회 평균) / 근거: MIT 동일 환경 60m → 1.67배 목표"

| | 정량 목표 예시 |
|---|---|
| ❌ 나쁨 | "매출 10억 달성" (활동·근거·조건 없음) |
| ❌ 나쁨 | "검출 정확도 99%" (측정 조건·비교 대상 없음 — 99%는 가짜 수치 의심) |
| ✅ 좋음 | "양산 라인 PoC 2건 수행을 통해 2027년 매출 8.4억 달성 (국내 6.0억 + 해외 2.4억, 계약의향서 3건 기반, [목표], financial-model.xlsx)" |
| ✅ 좋음 | "표면결함 검출 F1 ≥0.90 (OO-Bench v2 1만장, 동일 GPU, 5회 평균) / 근거: 공개 SOTA 0.91, 2027 Q2까지" |

### 6.2 정성 목표 공식

```
정성 목표 = 측정 가능한 상태 변화
```

- 막연한 "향상/제고/강화"는 금지. **무엇이 어떤 상태에서 어떤 상태로 바뀌는지**를 측정 가능하게.

| | 정성 목표 예시 |
|---|---|
| ❌ 나쁨 | "인지도 향상" / "기술 경쟁력 강화" |
| ✅ 좋음 | "정규 인력 N명 고용으로 1인 창업 → 조직 단위 기업으로 전환" |
| ✅ 좋음 | "PoC 단계 기술을 양산 적용 레퍼런스 보유 단계로 전환 (TRL 6 → 8)" |

### 6.3 목표는 하나의 흐름으로 연결

목표들을 따로 나열하지 말고 **사슬**로 잇는다: 콘텐츠/기술 → 유통/판로 → 매출 → 조직. **투자 유치는 목표가 아니라 성과의 결과**로 배치한다(improvement-research §B).

## 7. 좋은 섹션 vs 나쁜 섹션 (Before / After)

### 예시 A — 문제 인식 섹션

**Before (나쁨 — 모호·무근거)**
> 최근 많은 중소 제조기업이 품질관리에 어려움을 겪고 있습니다. 기존 방식은 비효율적이고 비용이 많이 듭니다. 본 사업은 혁신적인 AI 기술로 이 문제를 효율적으로 해결합니다.

문제점: "많은", "비효율적", "비용이 많이", "혁신적", "효율적" — 모두 모호어이고 출처가 없다. 평가자 질문("어떤 고객의 어떤 문제가 얼마나 심각한가")에 답하지 못한다.

**After (좋음 — 한 문장 답 + 근거 + 단위)**
> **종업원 50인 미만 금속가공 업체는 품질 불량 1건을 평균 12분에 걸쳐 육안·수기로 검사하며, 검사원 의존도가 높아 야간조 불량 검출률이 주간조의 절반에 그친다.**
>
> 검사 1건 12분은 OO조합 8개사 현장 인터뷰에서 확인했다([사실], interview-transcript L210, source-index #7). 야간조 검출률 격차는 KOSHA 2023 보고서의 교대조별 품질지표를 인용했다([사실], source-index #11). 이 두 사실로 "검사 인력 의존 → 시간대별 품질 편차"라는 핵심 문제가 성립한다.

개선점: 첫 문장이 평가자 질문에 직접 답한다(굵게). 모든 수치에 증거 태그와 행번호가 붙는다. 모호어가 사라졌다.

### 예시 B — 기술 차별성 섹션

**Before (나쁨)**
> 우리 기술은 경쟁사보다 정확도가 높고 속도가 빠릅니다. AI를 활용하여 기존 제품과 차별화됩니다.

문제점: 비교 대상·조건·수치가 없다. "AI 활용"은 차별점이 아니라 보편 기능이다(PRD §8.4 모호어).

**After (좋음)**
> **동일 데이터셋(OO-Bench v2, 1만 장)에서 본 모델의 불량 검출 F1은 0.91로, 공개 베이스라인(0.84)보다 0.07 높다. 단 이 수치는 연구 환경 측정값이며 현장 라인 검증은 [확인 필요]다.**
>
> 0.91/0.84 비교는 같은 데이터셋·같은 지표 조건이다(benchmark-comparison.xlsx, source-index #22; 7대 규칙 #6 — 조건 다른 벤치마크 단순 비교 금지). 현장 조명·이물 조건에서의 재현은 PoC 과제로 분리해 `execution.milestones`에 반영했다([목표]).

개선점: 비교 조건을 명시하고, 연구 성능과 제품 성능을 분리하며, 검증되지 않은 부분을 `[확인 필요]`/`[목표]`로 정직하게 둔다.

### 예시 C — 시장 규모 섹션 (★ 추가)

**Before (나쁨)**
> 국내 스마트팩토리 시장은 매우 크며 빠르게 성장하고 있습니다. 우리는 이 거대한 시장의 일부만 차지해도 큰 매출을 올릴 수 있습니다.

문제점: 무출처(탈락 결함 #1), "매우 큰/빠르게" 모호어, "일부만 차지" = 과도 추정의 전형(결함 #4). TAM만 있고 SOM 없음.

**After (좋음)**
> **본 사업의 SOM(3년 내 확보 가능 매출)은 18.6억원이다. 국내 머신비전 검사 시장 TAM 1.2조원(KOSIS) 중, 50인 미만 금속가공 SAM 940억원(필터 7.8%)에서 도달 가능한 보수적 점유율 2%를 적용했다.**
>
> | 구분 | 산식 | 값 | 출처·태그 |
> |---|---|---|---|
> | TAM | 국내 머신비전 검사 시장 | 1.2조원 | KOSIS, 조회일 2026-06-15, #14 [사실] |
> | SAM | TAM × 7.8%(50인 미만 금속가공 비중) | 940억원 | KOSIS 사업체조사 #15 [추정] |
> | SOM | SAM × 2%(3년 내 보수적 점유) | 18.6억원 | bottom-up: 124개사 × 1,500만원 ARPA [목표] |
>
> SOM은 top-down 점유율이 아니라 bottom-up(타깃 124개사 × 연 1,500만원)으로 교차 검증했다. 보수적 2%를 택한 이유는 초기 3년 영업 인력 2명 기준 도달 가능 고객 수 상한이기 때문이다(financial-model.xlsx L30).

개선점: SOM을 bottom-up으로 교차 검증, 모든 수치에 출처·조회일·태그, 보수적 추정의 *이유*까지 명시.

## 9. 분량 가이드 (★ 추가)

> "디테일하게"가 "길게"는 아니다. **공고 페이지 제한 준수가 1순위다 — 초과는 감점, 때로는 형식 미달로 자동 탈락이다.**

1. **공고 페이지 제한이 절대 상한.** `06-template-design/template-structure.yaml`의 페이지·분량 제약을 먼저 확인. 제한 내에서만 작성한다.
2. **제한 내에서 밀도를 높여 "디테일"을 확보한다.** 분량이 부족하다고 filler 문장으로 채우지 말 것. 같은 페이지를 **표·도식으로 정보 밀도를 올리는 방식**으로 디테일을 확보한다(표 1개 = 문장 5개 분량의 정보).
3. **배점 비중에 분량을 비례 배분.** 평가 배점표(`01-notice-analysis/evaluation-criteria.md`)에서 가중치 높은 항목에 페이지를 더 준다. 15점짜리 항목과 5점짜리 항목에 같은 분량을 쓰지 않는다.
4. **빈 섹션·filler 금지.** "본 사업은 매우 중요하다" 같은 내용 없는 문장, 같은 말의 반복, 미사여구는 디테일이 아니라 노이즈다 → 삭제하고 그 공간에 근거·표를 넣는다.
5. **표가 길면 분할**(improvement-research §H): 연도 Y1~3/Y4~5, 비목 직접비/간접비 블록. 폰트를 줄이기보다 표를 나눠 가독성을 지킨다.
6. **분량 부족 ≠ 채우기.** 채울 디테일(근거·수치·표)이 정말 없다면 그것은 리서치·인터뷰 부족 신호다. filler가 아니라 Gate 1·2로 되돌아가 근거를 더 확보한다.

## 11. R&D·정부 계획서 충실도 강화 (분량·리서치 편입·비교표·연차 상세 · 2026-06-18)

> **출처: 사용자 피드백.** "퀄리티는 올랐지만 양이 너무 적다 / 리서치가 본문에 거의 안 담겼다 / 경쟁·논문·특허 비교표가 없다 / 연차별 기술이 부실하다 / 다이어그램이 부족하다 / PDF에서 다이어그램이 깨진다." 이 6가지가 R&D 계획서 1순위 미달 사유다. 아래를 **충실도 게이트**로 강제한다.

### 11.1 리서치 본문 편입 의무 (최악의 안티패턴 = 조사하고 안 쓰기)

- Gate 2 리서치(`04-research/`, `source-index.xlsx`)의 핵심 발견을 **본문의 표·서술로 충실히 옮긴다.** 보고서에만 있고 본문에 없으면 리서치를 안 한 것과 같다.
- 목표: 본문이 `source-index` 출처의 **절반 이상**을 실제 인용. 시장 통계·정책·경쟁·논문·특허가 각각 본문에 표/문장으로 등장해야 한다.
- "리서치 결과 요약은 보고서 참조" 한 줄로 떼우지 않는다 — 평가위원은 보고서를 안 본다. 본문에 옮긴다.

### 11.2 필수 비교표 3종 (R&D — 하나라도 없으면 미완)

| 비교표 | 컬럼(필수) | 근거 |
|---|---|---|
| **① 경쟁제품/솔루션 비교표** | 제품·기업 / 측정기준 / 핵심성능 / 가격·모델 / 레퍼런스 / 약점 / 자사 대비 | 5~10개, 직접·간접·잠재 3분류, **측정기준+근거 컬럼 필수**(§5.2). 자사 행 포함, 불리한 항목도 정직히 |
| **② 논문/벤치마크 비교표** | 모델·기법 / 데이터셋 / 지표·성능 / 측정조건 / 동료평가·프리프린트 / 시사점 | 핵심 SOTA 5~10편. 조건 다른 벤치마크 단순비교 금지, 연구환경≠제품 구분(7대 규칙 #6) |
| **③ 특허 비교표** | 번호 / 출원인 / 출원일 / 상태 / 청구요지 / 우리와 관계 / 회피·차별 전략 | 최근접 선행 5~10건. 변리사 검토 대상 표시, 등록특허 공백=차별성 근거 |

### 11.3 연차별 기술내용 상세 (각 연차 최소 0.5~1페이지)

연차마다 아래를 **표 + 서술**로 전개한다. "1년차: AI 개발" 같은 한 줄 금지.

```
연차 목표 → 세부 개발항목(3~6개) → 각 항목의 핵심 기술·방법 → 산출물(deliverable)
         → 정량목표(§12 공식) → 검증방법(데이터·지표·시험)
```

- 세부 개발항목 표: `개발항목 | 세부 내용·방법 | 산출물 | 정량목표 | 담당`.
- RFP·성과지표가 있으면 연차별 정량목표를 그대로 매핑하고, 달성 방법을 기술적으로 풀어쓴다.

### 11.4 다이어그램 최소 8종 (R&D)

문제구조도 · 시스템 아키텍처 · 데이터 플로우 · (도메인) 처리 파이프라인 · 추진체계도 · 추진일정 간트 · 사업화 로드맵 · TRL 단계도 · 시장규모 차트 중 **8종 이상**. 한 그림 한 메시지(§09-diagrams 규칙).

### 11.5 분량 — 디테일 밀도로 채운다 (공고 제한 내)

- 공고 페이지 제한이 **절대 상한**(§9). 그 안에서 **표·도식·비교·연차상세·리서치 근거로 정보 밀도를 최대화**해 충실한 분량(R&D 통상 40~55쪽)을 확보한다.
- filler·미사여구로 채우지 않는다(§9.4). 분량은 **근거·표·다이어그램**으로 채운다. 분량이 안 나오면 리서치·인터뷰 부족 신호다(§9.6).

### 11.6 다이어그램 PNG 렌더 — PDF/DOCX/HWPX 필수 (사용자 지적 직접 반영)

- 초안 md 에는 다이어그램을 ` ```mermaid ` 코드블록으로 작성한다(HTML 은 자동 렌더).
- **DOCX/HWPX/PDF 변환 전 반드시 `scripts/prerender_mermaid.py`로 mermaid→PNG 치환한 "렌더 md"를 만들어 변환한다.** 코드블록을 그대로 변환하면 다이어그램이 텍스트로 깨진다(사용자 지적).

```bash
# 1) DOCX/HWPX/PDF 용: mermaid → PNG 치환
python3 scripts/prerender_mermaid.py \
  08-draft/business-plan-draft.md 08-draft/business-plan-draft.render.md \
  --img-dir 07-diagrams/images --src-dir 07-diagrams/diagram-source --prefix fig
# 2) 변환은 render.md 로
python3 scripts/md_to_docx.py 08-draft/business-plan-draft.render.md 10-final/final-business-plan.docx
npx tsx scripts/build_hwpx.mts 08-draft/business-plan-draft.render.md 10-final/final-business-plan.hwpx
bash scripts/to_pdf.sh 10-final/final-business-plan.docx 10-final/
# 3) HTML 은 원본 md(mermaid 자동렌더)
python3 scripts/md_to_html.py 08-draft/business-plan-draft.md 10-final/final-business-plan.html --base-dir 07-diagrams/images
```

- mmdc 미설치 시: 스킬 루트에서 `npm install @mermaid-js/mermaid-cli`(로컬) → `node_modules/.bin/mmdc` 를 `prerender_mermaid.py`가 자동 사용.
- 렌더 후 PNG 1~2장을 Read 로 한글 깨짐·잘림 검수(§12 픽셀 검수).
