# 01 — Gate 0 실행 프로토콜: 공고 분석

> SKILL.md가 **Gate 0 진입 시 Read**하는 상세 실행 프로토콜.
> 대상: PRD §7.1(프로젝트 생성) · §7.2(공고문 자동 수집).
> 목표: 공고 본문과 첨부를 확보하고, 평가 논리를 8개 산출물로 구조화한다.
> 산출물 위치: `bizplan-<slug>/01-notice-analysis/`

## 7대 절대 규칙 (이 단계에서의 의미)

- **임의 창작 금지**: 공고에 없는 배점·자격·일정을 추정으로 채우지 않는다. 공고에 명시가 없으면 `[확인 필요]`로 두고 사용자에게 묻는다.
- **출처 기록**: 각 추출 항목 옆에 `[출처: <파일명> p.<쪽>]` 또는 `[출처: <URL> 접근일 YYYY-MM-DD]`를 남긴다.
- **다운로드 실패 은폐 금지**: 받지 못한 파일은 반드시 목록으로 보고한다(PRD §26 신뢰성).
- 이 단계는 사실 추출이므로 `[추정][가정]` 태그를 거의 쓰지 않는다. 추출이 불확실하면 `[확인 필요]`.

## 0. 시작 전 체크

- `project.json`의 `document_type` 확정 여부 확인. 미확정이면 SKILL §발동 3번(문서 유형 게이트)로 돌아간다.
- 공고(URL/파일) 유무 확인. **공고가 없는 유형**(투자덱·내부 신사업 등)은 Gate 0을 건너뛰고 Gate 1로 간다. 이 경우 `01-notice-analysis/`에 `no-notice.md`(공고 없음 사유 1줄)만 남긴다.

## 1. 공고 URL/파일 수집 절차

### 1.1 입력 접수

사용자에게서 다음 중 하나 이상을 받는다(PRD §7.2 사용자 입력).

- 공고문 URL
- 공고명 / 주관기관명 (URL 탐색 단서)
- 첨부파일 직접 업로드 (`00-source/attachments/`에 사용자가 직접 둠)

### 1.2 자동 수집 (`scripts/fetch_notice.py`)

```bash
python3 ~/.claude/skills/bizplan/scripts/fetch_notice.py "<공고 URL>" --out bizplan-<slug>/00-source/
```

스크립트가 수행하는 동작(PRD §7.2 시스템 동작 1~7) 및 클로드의 확인 책임:

1. **본문 저장** → `00-source/notice/notice-page.html` + `notice-page.md`. 본문이 비었으면 사용자에게 직접 텍스트 붙여넣기를 요청.
2. **첨부 링크 탐색** → 페이지 내 `.pdf .hwp .hwpx .docx .xlsx .zip` 링크 수집.
3. **다운로드** → `00-source/attachments/`. PDF/HWP/HWPX/DOCX/XLSX/ZIP 대상.
4. **ZIP 해제** → ZIP은 같은 이름 폴더로 풀고 내부 파일을 종류별로 분류(`00-source/attachments/<zip명>/`).
5. **버전 비교** → 파일명·수정일로 정렬, 같은 문서의 `v1/v2/최종/수정본` 추정.
6. **최신/구버전 구분** → 최신본을 `latest`로 표시, 구버전은 `00-source/attachments/_old/`로 분리(원본 보존).
7. **실패 목록** → 받지 못한 링크는 `00-source/download-failures.md`에 `[URL · 사유(403/타임아웃/로그인필요/유료)]`로 기록.

### 1.2b 동적 사이트(JavaScript 렌더) 대응 — IRIS·나라장터 등 (가드레일 · 2026-06-17 IRIS 사고)

정부 R&D 포털(예: **IRIS** `iris.go.kr`)은 본문·첨부 링크를 **JavaScript로 동적 렌더**한다. `fetch_notice.py`(urllib)는 이때 **빈 골격(메뉴만)** 만 받고 첨부 0건이 된다. 증상: page.txt에 공고 본문이 없고 "IRIS 소개/사업소개" 같은 네비게이션만 보임. 이때 순서:

1. **본문**: Chrome 브라우저(`claude-in-chrome`)로 URL을 열고 `get_page_text`로 렌더된 본문을 추출 → `00-source/notice/page.txt`에 저장. (urllib 결과는 폐기)
2. **첨부 URL 확보**: 페이지의 첨부 링크를 `find`로 찾고, `read_network_requests`를 **켠 상태에서** 각 링크를 `computer left_click` → 발생하는 다운로드 요청(예: IRIS `fileDownload.do?atchDocId=...&atchFileId=...&_EndOffset=...`)을 네트워크 로그에서 수집. (링크가 onclick JS라 href 직접 추출은 쿠키 차단될 수 있음)
   - ⚠️ 브라우저 클릭 다운로드 자체는 자동화 환경에서 **503**으로 막히기도 한다. 그래도 **요청 URL은 네트워크 로그에 남는다**.
3. **다운로드**: 확보한 URL을 `curl -sS -L -A "Mozilla/5.0" -o <out> "<url>"` 로 직접 GET. IRIS는 세션 쿠키 없이도 200으로 받힌다(검증됨). 시그니처 확인: HWPX/ZIP은 `PK`(zip), `file` 명령으로 검증.
   - 중복 클릭 시 동일 atchDocId로 요청이 합쳐져 일부 첨부 URL이 누락될 수 있다 → 빠진 첨부는 다시 클릭해 URL 확보.
4. 다운로드는 **권한 필요 행동**이므로 파일 수·출처를 사용자에게 알리고 진행. 받은 파일·실패는 `00-source/fetch-report.md`에 기록.

### 1.3 로그인·유료 자료

- 로그인이 필요한 사이트, 유료 보고서는 **우회하지 않는다**(PRD §3.2 비목표, SKILL Gate 0). 사용자에게 해당 파일의 직접 업로드를 요청하고 `download-failures.md`에 `[로그인 필요 — 사용자 업로드 요청]`으로 남긴다.

### 1.4 파일 파싱

- **HWPX** (한/글 OWPML, 정부서식 다수): `scripts/hwpx_to_text.py <in.hwpx> [out.txt]` 로 본문 텍스트 추출(의존성 0). 표는 ` | ` 구분 근사. 추출 텍스트를 `00-source/attachments/extracted/`에 저장해 분석.
  ```bash
  python3 ~/.claude/skills/bizplan/scripts/hwpx_to_text.py "<첨부>.hwpx" "00-source/attachments/extracted/<이름>.txt"
  ```
- **PDF/DOCX/XLSX**: 텍스트 추출 후 분석.
- **.hwp(구버전 바이너리/OLE)**: `hwpx_to_text.py` 미지원 → 한/글 필요. 추출 실패 영역은 `[확인 필요]`로 표시하고 사용자에게 해당 쪽 캡처/요약 요청.

### 3.3 `evaluation-criteria.md` — **배점표 필수 (표)**

배점은 반드시 아래 4컬럼 표로 만든다. "우리 대응전략"은 인터뷰·리서치 결과를 가리키는 자리표시자로 시작하고 이후 채운다.

```markdown
# 평가 기준 — <공고명>

## 서면평가 배점표
| 평가 항목 | 배점 | 평가 관점(평가위원이 보는 것) | 우리 대응전략 |
|---|---:|---|---|
| 문제 인식 | 20 | 문제의 시급성·구체성·근거 | 인터뷰 1단계 + 시장 통계로 빈도/심각도 입증 |
| 실현 가능성 | 30 | 기술 성숙도·구현 단계·검증 | 프로토타입/PoC + 논문 TRL 연계 |
| 성장 전략 | 30 | 시장 규모·수익모델·확장 | TAM/SAM/SOM + 가격·채널 |
| 팀 구성 | 20 | 수행 역량·역할 분담 | founder-market-fit + 역할표 |
| 합계 | 100 | | |
[출처: 공고문 별표 p.X]

## 발표(대면)평가
- 방식 / 시간 / 질의응답: [출처: …]
- 발표 배점 비중(서면 대비): [출처: …]
- 예상 핵심 질문(평가 관점에서 역산): …

## 가점·감점
| 항목 | 가점/감점 | 조건 | 우리 해당 여부 |
|---|---|---|---|
```

> 이 배점표의 "평가 관점"·"우리 대응전략" 컬럼은 Gate 7(평가위원 시뮬)과 Draft(섹션별 key_message)로 그대로 이어진다. 배점이 높은 항목에 문서 분량·근거를 집중 배분한다.
