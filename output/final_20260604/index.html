2원문 보존 카드

입력 원문을 숨기지 않고 추적 가능하게 남기는 패턴입니다.

긴 원문을 기본 노출하면 모바일에서 지치므로, 기본은 접힌 카드로 둡니다. 핵심 요약과 원문은 분리합니다.

원문 전체 보기 · raw source preserved

원칙: 사용자가 제공한 원문은 분석과 분리해 보존합니다. 모델이 요약한 문장과 원래 문장을 섞지 않습니다.

  • 원문 출처와 날짜를 표기합니다.
  • 원문은 줄이지 않고, 필요한 경우 접어 둡니다.
  • 분석 섹션은 원문 카드 밖에서 작성합니다.

게이트 15분

문서 구조 & 단일 h1

  • PASS<h1> 1개, 제목 단계 건너뛰기 없음
  • PASSheader/nav/main/footer 랜드마크 확인
  • FAIL제목·목록을 div와 br로 흉내냄
게이트 25분

키보드 내비게이션

30실패 모드와 배포 완료 기준

체크리스트 이후에도 자주 새는 실패 모드와 “배포해도 좋다”는 완료 신호를 한 섹션으로 묶었습니다.

체크리스트를 돌렸는데도 빠져나가는 단골 패턴입니다. G2 운영 리포트에서는 “증상 → 숨은 원인 → 30초 확인법 → 최소 조치” 순서로 바로 재현 가능하게 남깁니다.

함정

ARIA를 “고치는 약”으로 오해하기

role과 aria-*는 동작을 만들어주지 않습니다. 역할을 선언했다면 키보드 활성화, 포커스, 상태까지 함께 구현해야 합니다.

해결

네이티브 먼저, ARIA는 보강

버튼·링크·체크박스·셀렉트는 네이티브 요소가 기본 접근성을 처리합니다. ARIA는 네이티브로 표현할 수 없는 패턴에만 씁니다.

사례

자동 점수 100점이어도 버튼은 안 눌릴 수 있다

<div onclick> 결제 버튼은 점수로 놓치기 쉽습니다. 게이트 2처럼 사람이 Tab으로 핵심 흐름을 끝까지 확인해야 잡힙니다.

3완료 기준 — 배포해도 좋다는 신호

아래를 모두 “예”로 답할 수 있을 때만 G2 게이트를 엽니다. 하나라도 “아니오”면 멈추거나, 책임자 승인과 함께 예외를 기록합니다.

  1. 구조 — h1은 1개이고 제목 단계가 건너뛰지 않으며, main 랜드마크가 정확히 1개다.
  2. 키보드 — 마우스 없이 핵심 흐름을 처음부터 끝까지 마쳤고, 모달·메뉴 어디에도 갇히지 않았다.
  3. 포커스·대비 — Tab 이동 시 초점이 항상 보이고, 본문 대비와 포커스 대비가 기준을 만족한다.
  4. 폼 — 모든 입력은 라벨·도움말·오류 메시지와 연결되어 있고, 오류는 색만으로 전달하지 않는다.
  5. 의미 — 의미 있는 이미지는 alt를 갖고, 버튼·링크는 네이티브 요소이며 잘못된 ARIA가 없다.
  6. 모바일·확대 — 390px와 200% 확대에서 가로 스크롤·텍스트 잘림·터치 타깃 충돌이 없다.
  7. 기록 — FAIL은 수정됐거나, 책임자·위험·만료일이 있는 예외 기록으로 남았다.

31Three Code Approaches

한 문제를 세 가지 구현 접근으로 비교하는 코드 판단 카드입니다. 현재 스타일에서는 “권장 접근”만 붉은 왼쪽 라인으로 강조합니다.

코드 비교장단점 카드JS 없이 정적 비교
Approach A

완전 탐색

모든 쌍을 확인합니다. 설명은 쉽지만 입력이 커지면 느립니다.

for i in range(n): for j in range(i+1, n): if nums[i]+nums[j] == target: return [i, j]
장점
  • 가장 단순
  • 메모리 O(1)
단점
  • 시간 O(n²)
  • 확장성 낮음
학습용작은 입력
Approach B · Pick

해시맵 1-pass

보수값을 저장하며 한 번만 순회합니다. 실무 기본 선택지입니다.

seen = {} for i, n in enumerate(nums): need = target - n if need in seen: return [seen[need], i] seen[n] = i
장점
  • 시간 O(n)
  • 대규모 입력 안정
단점
  • 공간 O(n)
  • 해시 의존
권장실무 기본
Approach C

정렬 + 투 포인터

정렬 뒤 양끝 포인터를 좁힙니다. 원본 인덱스 보존이 관건입니다.

arr = sorted(enumerate(nums), key=lambda x: x[1]) l, r = 0, len(arr)-1 while l < r: s = arr[l][1] + arr[r][1]
장점
  • 정렬 데이터 재사용
  • 직관적 탐색
단점
  • O(n log n)
  • 인덱스 추적 복잡
정렬 의존비교 대안
