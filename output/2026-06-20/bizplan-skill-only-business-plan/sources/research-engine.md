## 0. 절대 원칙 — 조사와 작성의 분리 (7대 규칙 #4)

```text
1단계  research-plan.md 작성        ← 무엇을 / 왜 / 어디서 조사할지 먼저 확정
2단계  조사 실행 + source-index 즉시 등재   ← 결론 없이 자료부터 수집
3단계  research-report.md 작성       ← 조사가 끝난 뒤 결론을 쓴다
4단계  사업계획서에 쓸 근거 선별       ← 보고서에서 코어로 끌어올 행만 고른다
```

- **조사 전에 결론을 쓰지 않는다.** "시장이 크다"를 먼저 정하고 근거를 찾으면 출처 편향(§7)이 발생한다.
- research-plan.md 없이 WebSearch를 시작하지 않는다. 계획 파일이 게이트다.
- 사업계획서 본문 문장은 Gate 2에서 쓰지 않는다. 이 단계의 산출은 보고서 + 출처 인덱스뿐이다.

## 1. research-plan.md 구조 (단계 6 · `03-idea-and-title/research-plan.md`)

조사를 시작하기 전에 아래 9개 항목을 모두 채운다. 빈 항목이 있으면 조사 진입 금지.

```markdown
# 리서치 계획

## 1. 조사 목적
- 이 리서치가 검증/뒷받침해야 할 사업 가설 1~3개

## 2. 핵심 질문 (조사로 답할 질문)
- Q1. 국내 시장 규모와 성장률은? (TAM 산식 근거)
- Q2. 직접 경쟁 제품 N개의 가격·기능·약점은?
- Q3. 이 기술의 상용화 수준(TRL)은?
- ... (항목당 답이 나오면 어느 보고서 섹션에 들어가는지 표기)

## 3. 검색 키워드
- 1차 키워드 / 2차 조합 키워드 / 제외어

## 4. 한글·영문 동의어
- 한글: [용어] = [동의어1, 동의어2]
- 영문: [term] = [synonym1, synonym2]
- (업계 약어·제품 카테고리명·표준 용어 포함)

## 5. 조사 대상 국가
- 국내 / 미국 / 유럽 / 일본·중국 등 (사업 진입 시장 기준)

## 6. 조사 기간
- 시장 통계: 최근 N년 / 기술·논문: 최근 N년 / 정책: 현행 + 예고

## 7. 우선 출처 (§3 우선순위에서 본 사업에 맞는 출처 명시)
- 예: KOSIS, 중기부 통계, 산업협회 X, 기업 공시

## 8. 필요한 수치
- TAM/SAM/SOM 산식에 필요한 입력값 목록 (없으면 [확인 필요])
- 가격대, 고객 수, 침투율, 객단가 등

## 9. 검증할 사업 가설
- 가설 → 확증 시 근거 / 반증 시 근거 (양쪽 모두 명시)
```

> 작성 팁: 핵심 질문(2)과 필요한 수치(8)는 나중에 `business-core.yaml`의 어느 필드를 채울지를 역으로 적는다. 코어에 못 들어가는 조사는 범위 밖이다.

## 3. 출처 우선순위 10단계 (PRD §10.3)

같은 주장에 출처가 여럿이면 **번호가 작은 출처를 우선** 인용한다.

| 순위 | 출처 |
|---|---|
| 1 | 정부·공공기관 (통계청, 부처, 진흥원) |
| 2 | 법령과 정책 문서 |
| 3 | 기업 공시 (사업보고서, DART 등) |
| 4 | 특허청·공식 특허 데이터베이스 |
| 5 | 학술논문과 연구기관 |
| 6 | 산업협회 |
| 7 | 기업 공식 홈페이지 |
| 8 | 신뢰할 수 있는 시장조사기관 |
| 9 | 신뢰할 수 있는 언론 |
| 10 | 제품 리뷰·사용자 커뮤니티 |

### 3-A. 한국 통계·근거 출처 카탈로그 (우선순위 1~5의 실전 접근법)

위 우선순위가 "누구를 믿느냐"라면, 이 표는 "어디서 무엇을 어떻게 얻느냐"다. 1차 출처를 직접 추적할 때 이 카탈로그부터 본다. 언론이 인용한 수치는 반드시 아래 원천까지 거슬러 올라가 원문 위치(메뉴/검색어)를 기록한다(§6-A 황금률).

| 출처 | 무엇을 얻나 | 접근 방법 / 원문 위치 기록 예 | 순위 |
|---|---|---|---|
| **KOSIS** 국가통계포털 (kosis.kr) | 시장·인구·사업체수·산업별 매출·고용 등 공식 통계의 1차 원천. TAM Top-down 분모. | 국내통계 → 주제별/기관별 검색. 통계표 단위·기준연도 확인 후 표 그대로 인용. 기록: "KOSIS, [통계표명], OOOO년 기준 / 조회일 / 검색어 OO" | 1 |
| **DART** 전자공시 (dart.fss.or.kr) | 경쟁사·유사기업의 **매출·영업이익·시장점유 추정·사업구조**. 상장·일부 비상장 공시기업. | 공시통합검색 → 회사명 → 사업보고서/감사보고서 → 재무제표·사업의 내용. 기록: "DART, [회사] OOOO 사업보고서, [재무제표/사업의 내용] / 조회일" | 3 |
| **KIPRIS** 특허정보넷 (kipris.or.kr) | **선행기술·경쟁 특허·권리 관계**(특허/실용신안/디자인/상표). 기술 독창성·FTO 1차 검토. | 스마트검색 → 키워드/IPC/출원인. 출원·등록·소멸 상태 확인. 상세는 `05-patent-analysis.md`. 기록: "KIPRIS, 검색어 OO / IPC OO / 조회일 / 출원번호 OO" | 4 |
| **KISDI** 정보통신정책연구원 (kisdi.re.kr) | **ICT·미디어·플랫폼·통신** 시장 동향·이용행태·정책 연구보고서. | 발간물 → 보고서명. PDF 핵심 수치+표만 발췌, 원문은 부록. 기록: "KISDI, [보고서명], OOOO / 조회일 / p.OO" | 1 |
| **산업연구원(KIET)** (kiet.re.kr) | **산업 구조·전망·경쟁력 분석·산업별 성장률**. 제조·산업 정책 근거. | 연구자료 → 산업경제 분석. 기록: "KIET, [보고서명], OOOO / 조회일" | 1 |
| **진흥원·기관 시장보고서** (KOCCA·KOTRA·NIPA·KISA·진흥원 등) | 도메인별 시장규모·해외시장·이용자 통계(콘텐츠·수출·SW·보안 등). | 각 기관 발간물/통계 메뉴. 무료 공개분만. 페이월·로그인 우회 금지(§6). 기록: 기관명+보고서명+발행연도+조회일 | 6~8 |
| **나라장터·조달(g2b)·공공데이터포털** | 공공 발주·수요 규모(B2G 사업), 발주 건수·금액으로 SOM Bottom-up 근거. | 입찰공고/계약현황 검색어로 건수·금액 집계. 기록: "나라장터, 검색어 OO, OOOO~OOOO / 조회일 / 집계방법" | 1 |

- **원칙**: 우선순위 1~5 출처(정부·공시·특허·논문)가 **핵심 근거에 반드시 포함**돼야 Gate 2를 통과한다(§9 체크리스트). 시장조사기관·언론은 보조.
- 수치 하나에 여러 출처가 있으면 **번호 작은 출처를 본문에 인용**하고 나머지는 보강 근거로 부록에 둔다.

### 3-B. 근거 4유형별 신뢰도 판단 (수집 시점에 분류)

자료를 보는 즉시 어느 유형인지 정하고, 그 유형의 신뢰 기준으로 `source-index.xlsx` `reliability`(상/중/하)를 매긴다.

| 유형 | 무엇을 입증하나 | 우선 출처 | 신뢰도 ↑ 조건 | 신뢰도 ↓ 신호 |
|---|---|---|---|---|
| **시장 근거** | 시장규모·성장률·고객 수·수요 | KOSIS·KIET·KISDI·진흥원 | 공공·기준연도 명확·표본 큼·최신 | 출처 불명, 시장조사사 보도자료 재인용, 3년 초과 노후 |
| **기술 근거** | 기술 수준·성능·선행기술·TRL | KIPRIS(특허)·논문·표준문서 | 동일조건 시험·제3자 검증·등록특허 | 자체 측정만, 조건 미기재, 프리프린트 단독 |
| **실행 근거** | 실현 가능성·수행 실적·트랙션 | 자사 계약·MVP 로그·인터뷰 | 1차 증빙(계약서·로그·사진)·재현 가능 | 구상 단계 진술만, 증빙 없음 |
| **재무 근거** | 매출·비용·단가·점유율 | DART·자사 회계·산업 평균 | 공시·실거래·보수적 가정 | 낙관 단일 시나리오, 산식·가정 비공개 |

- `source-index.xlsx`의 `reference_date`(기준 시점)·`accessed_date`(조회일)·`priority_rank` 컬럼을 유형 판단에 함께 활용한다. **기준 시점과 발행일은 다르다**(§3 메타 #4·#5) — 2024년 시장규모를 2026년 보고서가 인용해도 기준 시점은 2024.
- 기술·재무 근거는 §5 부정적 근거(경쟁 강점·시장 축소)와 짝지어 수집해야 평가위원의 반대 질문을 견딘다.

### 자료마다 기록할 10개 메타 (예외 없음)

수집한 모든 자료는 아래 10개 필드를 채워 `source-index.xlsx`에 즉시 등재한다. 하나라도 비면 핵심 근거로 쓸 수 없다(7대 규칙 #3).

| # | 메타 | 비고 |
|---|---|---|
| 1 | 제목 | 자료 원제 |
| 2 | 발행기관 | 출처 우선순위 판정 근거 |
| 3 | 저자 | 없으면 기관명 |
| 4 | 발행일 | 자료가 만들어진 날 |
| 5 | 기준 시점 | 수치가 가리키는 시점(예: 2024년 기준 시장규모) — 발행일과 다름 |
| 6 | 접근일 | 우리가 본 날 (재현성, PRD §26) |
| 7 | URL / 문헌 식별자 | DOI·특허번호 등 |
| 8 | 사용 가능한 주장 | 이 자료에서 인용할 한 줄 |
| 9 | 신뢰도 | 상/중/하 (출처 순위 + 표본 + 최신성 종합) |
| 10 | 사업계획서 반영 위치 | 어느 섹션/코어 필드에 쓸지 |

## 4. source-index.xlsx 컬럼 명세 (`04-research/source-index.xlsx`)

`scripts/build_xlsx.py`로 생성. 컬럼 = §3의 10개 메타 + 관리용 3개.

| 컬럼 | 설명 |
|---|---|
| `id` | S001, S002 … 인용 시 이 ID를 본문에 단다 |
| `title` | 제목 |
| `publisher` | 발행기관 |
| `author` | 저자 |
| `published_date` | 발행일 (YYYY-MM-DD) |
| `reference_date` | 기준 시점 |
| `accessed_date` | 접근일 |
| `url` | URL / DOI / 특허번호 |
| `usable_claim` | 사용 가능한 주장 |
| `reliability` | 신뢰도 (상/중/하) |
| `target_section` | 반영 위치 |
| `stance` | 우호 / 중립 / **부정·반대** (편향 점검용, §5) |
| `priority_rank` | 1~10 (§3 출처 우선순위) |

> **자료를 보는 즉시 1행 추가.** "나중에 정리"는 금지 — 접근일·기준시점이 유실되고 환각 출처의 온상이 된다.

## 5. 출처 편향 방지 — 부정적 근거 의무 수집 (PRD §29, 7대 규칙 함의)

사업에 유리한 자료만 모으면 평가위원(특히 회의적 반대 평가자)을 통과하지 못한다. 아래 5종은 **반드시 능동적으로 검색**한다.

| 의무 수집 대상 | 검색 방향 |
|---|---|
| 부정적 근거 | "한계", "실패", "리스크", "limitations", "challenges" 키워드 결합 |
| 실패 사례 | 유사 사업·제품의 폐업·철수·피벗 사례 |
| 경쟁 강점 | 경쟁사가 우리보다 나은 점 (가격·기능·점유율) |
| 시장 축소 | 시장 정체·역성장·수요 감소 시나리오 |
| 규제 위험 | 인허가·개인정보·안전·환경 규제 및 강화 예고 |

- `source-index.xlsx`의 `stance` 컬럼에 **`부정·반대`로 분류된 행이 최소 몇 건은 있어야 한다.** 0건이면 편향 의심 → 재조사.
- research-report.md §18(위험요소)에 이 자료들을 모은다. 위험을 숨기지 않고 "대응 방안"과 함께 적는다.

|---|---|---|
| 키워드로 후보 찾기 | `WebSearch` | research-plan.md §3·§4 키워드·한영 동의어를 조합. 1차 → 2차 좁히기 |
| 본문·수치 추출 | `WebFetch` | 검색으로 찾은 URL에서 실제 수치·표·발행일을 가져와 메타 10개 채움 |
| 통계 원천 확인 | `WebFetch` | 언론 인용 수치는 1차 출처(정부·협회 원자료)까지 추적 |

### 접근 금지·우회 금지 (PRD §3.2 비목표, §26 보안)

- **로그인 필요 사이트·유료 시장조사 보고서는 우회하지 않는다.** 무단 접근·페이월 우회 금지.
- 유료/로그인 자료가 필요하면 사용자에게 직접 요청하거나, 무료 공개 출처로 대체하고 그 사실을 명시한다.
- 검색으로 수치를 못 찾으면 **만들어내지 않는다.** `[확인 필요]`로 두고 missing 항목으로 보고(7대 규칙 #1).
- 검색어는 모두 저장한다(PRD §26 재현성) — research-plan.md §3 또는 노트에 실제 사용한 쿼리를 적는다.

## 6-A. 통계 인용 황금률 (평가위원 검증을 견디는 인용법)

수치 한 줄이 사업계획서의 신뢰를 만들거나 무너뜨린다. 모든 통계는 **30초 안에 검증 가능**해야 한다.

### 표기 3요소 — 모든 핵심 통계에 필수

```text
출처명 + 조회일 + 원문 위치(메뉴/검색어)
예) "나라장터(검색어 'OO 구축', 2023~2025) / 조회일 2026-01-13 / 본문 2.2절"
예) "KOSIS, 사업체수 통계(2024년 기준) / 조회일 2026-01-13 / 산업분류 OO"
```

- 이 3요소는 `source-index.xlsx`의 `publisher`·`accessed_date`·`url`/`usable_claim` 컬럼과 1:1 대응한다. 원문 위치(메뉴 경로·검색어)는 `usable_claim` 또는 비고에 함께 적어 **평가위원이 같은 경로로 재현**할 수 있게 한다.

### 스크랩 금지 — 공식 원본의 핵심 수치+표만

- ❌ 기사·블로그·요약글 **전체 스크랩 금지**. 언론이 인용한 수치는 1차 출처(정부·협회·공시 원자료)까지 추적해 그 원본을 인용한다(§3-A).
- ✅ 본문에는 **핵심 수치 + 표 1개**만. 긴 원문·캡처·맥락은 **부록**으로 빼고 본문에서 "(부록 N)" 참조.
- ✅ 같은 수치가 여러 곳에 있으면 우선순위 가장 높은(번호 작은) 출처 1개만 본문, 나머지는 보강.

### 설득 3요소 (수치를 쓸지 판단)

| 요소 | 질문 |
|---|---|
| 검증가능성 | 평가위원이 30초 안에 같은 수치를 확인할 수 있는가? (출처·메뉴·검색어가 있는가) |
| 출처 신뢰도 | 공공·공식·제3자 검증 출처인가? (§3 우선순위 1~5인가) |
| 최신성 | 기준 시점이 사업 판단에 유효한가? (노후 수치면 [확인 필요] 또는 최신 자료 보강) |

세 가지 중 하나라도 약하면 본문 핵심 근거로 쓰지 않는다.

### 불리한 표현 자동 교정 (과장 = 감점)

| 위험 표현 | 교정 |
|---|---|
| "국내 유일" | "유사 사례 미확인(부록 N에 조사 범위·검색어 명시)" |
| "100% 개선" / "10배" | "동일 조건 대비 X% (측정방법·근거 부록 N)" |
| "최고의" / "혁신적" | 측정 가능한 비교 수치로 치환하거나 삭제 |
| 출처 없는 시장 수치 | [확인 필요]로 두고 §20 추가 검증 과제로 |

> 평가위원은 과장된 한 줄로 문서 전체를 의심한다. **보수적이고 검증 가능한 표현이 신뢰를 만든다.**

## 6-B. 경쟁·기술 조사 디테일

### 경쟁사 3분류 (5~10개 수집)

| 분류 | 정의 | 조사 포인트 |
|---|---|---|
| **직접** | 같은 고객·같은 문제·유사 제품 | 가격·핵심기능·점유율·약점. DART로 매출·구조 추적 |
| **간접** | 다른 방식으로 같은 문제 해결 | 전환 가능성·고객 겹침 |
| **잠재** | 진입 예정·인접 사업자 | 진입 신호(특허 출원·채용·투자)·진입 시점 |

### 비교표 — 측정기준 + 근거 컬럼 필수 (공정성)

- 핵심 비교 기준 3~5개(가격·기능·점유율·만족도)를 고른다.
- 각 기준에 **"측정기준" 컬럼**(무엇을 어떻게 쟀는지)과 **"근거" 컬럼**(source-index ID)을 둔다. 측정기준 없는 비교는 "우리가 더 좋다"는 주장일 뿐 평가위원이 기각한다.
- **성능 수치는 동일 조건 시험·제3자 검증**만 비교한다. 자사 측정 ↔ 경쟁사 공칭값을 나란히 놓지 않는다(조건 다름). 비교 불가하면 "동일 조건 비교 불가, 자사 OO 조건 측정값"으로 명시.
- 포지셔닝맵(2속성 축 → 빈 공간 = 차별점) + SWOT으로 보강.
- 차별성 = "왜 우리가 더" + "**경쟁사가 못 하는 구조적 이유**" + 진입장벽. 단순 기능 나열은 차별성이 아니다.

### 기술 선행조사

- **특허**: KIPRIS로 선행기술·경쟁 특허 검색 → 독창성·회피 가능성 1차 검토. 상세 절차·claim chart는 `05-patent-analysis.md`.
- **논문**: 핵심 기술의 선행연구·벤치마크·TRL. 조건 다른 벤치마크 단순 비교 금지, 프리프린트 ≠ 동료평가. 상세는 `06-paper-analysis.md`.
- 두 결과는 §5 부정적 근거(경쟁 우위 특허·재현 실패 사례)와 함께 모은다.

## 6-C. 시장규모 TAM / SAM / SOM (financial-models.md와 연결)

시장규모는 **두 방향으로 교차 검증**한다. 산식·입력값은 `05-business-core/market-sizing.xlsx`에, 수식 표준은 `references/financial-models.md`에 둔다.

| 지표 | 정의 | 방법 |
|---|---|---|
| **TAM** | 전체 시장 (이론적 최대) | **Top-down**: 공신력 기관(KOSIS·KIET·진흥원) 전체시장 × 조건 비율 축소 |
| **SAM** | 우리가 도달 가능한 시장 | TAM × 지역·세그먼트·채널 필터 % |
| **SOM** | **3년 내 실제 가져올 돈** (핵심) | **Bottom-up 필수**: 잠재고객 수 × ARPA(고객당 평균 매출). 영업·채널 용량으로 검증 |

```text
TAM(Top-down) = 공신력 전체시장 규모 × 조건 비율
SAM           = TAM × 도달가능 필터(지역/세그먼트/채널) %
SOM(Bottom-up)= 잠재 고객 수 × ARPA × 현실적 점유율  ← 투자자·평가위원이 가장 본다
```

- **SOM이 핵심**이다. "3년 내 실제 가져올 돈"을 잠재고객×ARPA로 **bottom-up**으로 쌓아 올린다. TAM만 크고 SOM 근거가 약하면 가장 흔한 탈락 사유(§C/D 디테일 체크리스트).
- **보수적 추정이 신뢰를 높인다.** 과도한 점유율 가정(예: 1년차 시장 10% 장악)은 감점. 점유율 가정에도 근거(채널 용량·영업 인력·전환율)를 단다.
- TAM의 분모(전체시장)는 §3-A 공공 통계로, SOM의 입력(고객 수·ARPA·전환율)은 인터뷰 확정사실·실거래로 채운다. 입력값이 없으면 만들지 말고 `[확인 필요]`.
- TAM↔SOM의 비율이 비현실적으로 크거나(SOM이 TAM의 거의 0%) 작으면(과장) 재검토한다.

## 7. research-report.md 작성 (단계 10 · `04-research/research-report.md` + `.docx`)

조사가 끝난 뒤 작성. PRD §13.2의 **21개 목차 순서를 그대로** 따른다.

```text
1.  조사 개요
2.  사업 아이디어와 핵심 가설
3.  사회적 동향
4.  경제적 동향
5.  정책과 규제
6.  산업 구조와 업계 동향
7.  국내 시장
8.  해외 시장
9.  고객과 수요
10. 국내 경쟁 제품
11. 해외 경쟁 제품
12. 경쟁회사
13. 주요 기술
14. 논문과 연구 동향        ← 06-paper-analysis 산출 요약
15. 특허 동향과 권리 분석    ← 05-patent-analysis 산출 요약
16. 사업모델과 수익성
17. 진입 장벽
18. 위험요소                ← §5 부정적 근거를 여기 모음
19. 사업계획서에 활용할 핵심 근거   ← 코어로 끌어올 행 선별 (조사→작성 경계)
20. 추가 검증 과제          ← [확인 필요] 항목 집계
21. 참고문헌과 출처          ← source-index.xlsx와 1:1 대응
```

### 섹션 작성 형식 (PRD §13.3 — 매 섹션 동일하게)

```text
핵심 결론        한 문장. 평가위원이 이 섹션에서 가져갈 결론.
→ 근거 자료      source-index ID(S0xx)를 단다. 출처 없는 결론 금지.
→ 표·그래프      수치는 표/그래프로. 제목·단위·기준일·출처 표기.
→ 해석          숫자가 의미하는 바.
→ 사업에 미치는 영향   우리 사업에 유리/불리한 함의.
→ 사업계획서 반영 위치  어느 섹션·코어 필드로 가는지.
```

- 모든 수치에 `[사실]/[추정]/[가정]/[목표]/[확인 필요]` 태그를 붙인다(7대 규칙 #2).
- §19는 보고서 전체에서 **사업계획서에 실제로 인용할 근거만** 추려 모은다. 이것이 Gate 3(코어)의 입력이다.

## 8. 병렬 리서치 dispatch (대량일 때)

시장·경쟁·특허·논문·사업성은 독립적이므로 `Task`로 동시 실행(SKILL.md §병렬 리서치). 각 서브에이전트에게 **반드시 전달**:

1. `business-core.yaml`(현재본) + `research-plan.md` 경로
2. 출처 우선순위 10단계 + 증거 태그 규칙 + source-index 컬럼
3. 산출 파일 경로 (자기 폴더만)
4. 7대 절대 규칙 (특히 #1 창작 금지, #3 출처 기록, §5 부정적 근거 의무)

서브에이전트는 컨텍스트를 공유하지 않으므로 위 4개를 매번 명시. 메인은 반환된 노트·source-index 행을 통합하고 충돌만 조정한다.
