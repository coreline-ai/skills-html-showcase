# 증거 태깅 — 이 스킬의 신뢰성 핵심 문서

> 7대 절대 규칙 #1·#2·#3의 실행 프로토콜. PRD §5.6(사실/추정/가정/목표 분리), §5.7(임의 창작 금지), §26(신뢰성) 기반.
> 모든 단계(인터뷰·리서치·코어·초안)에서 항상 적용된다. 위반 시 산출물 폐기.

좋은 사업계획서가 "글을 잘 써서"가 아니라 "반론을 견뎌서" 만들어지듯, 이 스킬의 신뢰성은 **모든 수치·주장이 어디서 왔는지 추적 가능한가**에 달렸다. 증거 태깅은 그 추적의 문법이다.

핵심 명제: **AI는 사실을 만들지 않는다. 모르면 정직하게 `[확인 필요]`로 둔다.**

---

## 1. 5개 태그 정의

모든 수치·주장 앞에 정확히 하나의 태그를 붙인다.

| 태그 | 의미 | 판단 기준 | 출처 연결 |
|---|---|---|---|
| `[사실]` | 확인된 정보 | 외부 출처 또는 사용자 1차 증거로 검증됨 | `source-index.xlsx` 행 **필수** |
| `[추정]` | 근거+계산식으로 도출한 수치 | 입력값(전부 [사실] 또는 명시된 [가정]) + 산식이 있음 | `evidence-ledger.xlsx`에 산식 + 입력 행 |
| `[가정]` | 미검증 전제 | 아직 확인 안 했지만 논의를 위해 둔 전제 | 가정 사유 명시(`assumptions.md`) |
| `[목표]` | 앞으로 달성하려는 성과 | 현재값이 아니라 미래의 약속 | 달성 조건·시점 명시 |
| `[확인 필요]` | 추가 자료가 필요한 항목 | 출처도 없고 가정으로 둘 수도 없음 | `follow-up-items.md` 항목 번호 |

### 태그 작성 형식

```text
[태그] 값 (근거/산식/출처행)
```

예:
- `[사실] 주 3회 발생 (interview-transcript L120, 사용자 직접 경험)`
- `[추정] TAM 1.2조원 (market-sizing.xlsx L3: 사업체수 12만 × ARPU 1,000만원)`
- `[가정] 도입 첫해 전환율 3% (동종 SaaS 업계 통념, 검증 전)`
- `[목표] 처리시간 8h→1h (PoC 검증 예정, 2026 Q2)`
- `[확인 필요] 해외 시장 규모 (follow-up #14, 유료 보고서 필요)`

## 2. 영역별 태그 선택 예시

같은 영역이라도 출처 상태에 따라 태그가 달라진다. "어느 태그인가"를 헷갈릴 때 본다.

### 시장 규모
| 상황 | 태그 |
|---|---|
| 통계청·KOSIS 등 공식 통계에서 직접 인용 | `[사실]` (source-index 행) |
| 공식 통계 입력값 + ARPU 가정으로 산출한 TAM | `[추정]` (산식 명시) |
| "글로벌 시장은 크다" 식 출처 없는 주장 | 금지 → `[확인 필요]` |

### 매출
| 상황 | 태그 |
|---|---|
| 작년 실제 매출 (세무·계약 자료) | `[사실]` |
| 가격 × 예상 고객수로 계산한 내년 매출 | `[추정]` (입력값 태그 명시) |
| "3년 내 100억" | `[목표]` (가정·시점 명시) |

### 고객 수
| 상황 | 태그 |
|---|---|
| 현재 계약 고객 12개사 | `[사실]` (계약서 근거) |
| 시장 점유율 가정 기반 잠재 고객 | `[추정]` |
| 첫해 목표 고객 50개사 | `[목표]` |

### 기술 성능
| 상황 | 태그 |
|---|---|
| 공개 벤치마크에서 측정한 F1 0.91 (연구 환경) | `[사실]` + "연구 환경" 명시 (7대 규칙 #6) |
| 현장 라인에서의 정확도 | 측정 전이면 `[목표]` 또는 `[확인 필요]` |
| 경쟁사 성능과의 비교 | 같은 조건이면 `[사실]`, 조건 다르면 비교 금지 |

### 특허
| 상황 | 태그 |
|---|---|
| 등록·법적 상태 확인된 특허 번호 | `[사실]` (특허DB 행) |
| 청구항 침해 가능성 판단 | `[확인 필요]` (변리사 검토 대상, 7대 규칙 #6) |
| 출원 가능 권리화 지점 | `[가정]`/`[목표]` (patent-opportunity.md) |

## 3. 태그 ↔ 원장(ledger) 연결 규칙

태그는 장식이 아니다. 추적 가능해야 한다.

- **`[사실]`은 반드시 `source-index.xlsx` 행과 연결.** 행에는 제목·발행기관·저자·발행일·기준시점·접근일·URL/문헌식별자·사용 가능한 주장·신뢰도·반영 위치가 있어야 한다(PRD §10.3).
- **`[추정]`은 반드시 `evidence-ledger.xlsx`에 산식 + 입력값 행.** 입력값은 전부 `[사실]`이거나 명시된 `[가정]`이어야 한다. 입력이 출처 없으면 추정 자체가 무효.
- **모든 Claim은 `evidence-ledger.xlsx`에 1행.** `claim_text / claim_type(사실·추정·가정·목표) / source(행참조) / confidence / target_section / verification_status`. 이것이 데이터 모델 Claim(PRD §25)의 실체다.
- **`business-core.yaml`의 모든 값에 태그 + 행참조.** 코어 값 → ledger 행 → source-index 행으로 이어지는 사슬이 끊기면 그 값은 미완성이다.

```text
business-core.yaml (tam: "[추정] 1.2조 (ledger L3)")
   └─ evidence-ledger.xlsx L3 (산식: 12만 × 1,000만, 입력행 → source-index #14, #15)
        └─ source-index.xlsx #14 (통계청 사업체수, 2024.12, 접근일 2026-06-17, URL)
```

## 4. AI 임의 창작 금지 체크리스트 (7대 규칙 #1)

아래 항목은 **사용자 1차 증거 또는 외부 출처 없이 절대 생성하지 않는다.** 없으면 `[확인 필요]`.

- [ ] **고객** — "주요 고객으로 OO사" 식 가상 고객 생성 금지. 실제 인터뷰·계약 근거만.
- [ ] **매출** — 과거·현재 매출을 추정으로 채우지 않는다. 실적은 `[사실]`만, 미래는 `[목표]`.
- [ ] **계약·MOU·LOI** — 존재하지 않는 계약을 만들지 않는다.
- [ ] **특허** — 보유하지 않은 특허·출원을 적지 않는다. 권리범위는 변리사 검토 전엔 단정 금지.
- [ ] **인증** — ISO·KC·GS 등 보유하지 않은 인증을 적지 않는다.
- [ ] **기술 성능** — 측정하지 않은 수치를 만들지 않는다. 연구 환경값을 제품값으로 쓰지 않는다.
- [ ] **시장 수치** — 출처 없는 시장 규모·성장률을 만들지 않는다. "업계 통념"도 `[가정]` 태그.
- [ ] **고객 반응·인터뷰** — 하지 않은 고객 인터뷰 결과를 만들지 않는다.

> 위반 신호: 초안에 코어/원장에 없는 수치·고유명사가 등장하면 즉시 멈추고 출처를 찾거나 `[확인 필요]`로 강등한다.

## 5. 생성 내용 vs 원문 인용 구분 (PRD §26 신뢰성)

- **원문 인용**은 출처·위치를 표기하고, 가능하면 큰따옴표 또는 인용 블록으로 둔다.
  - 예: > "전국 사업체 수는 약 12만 개" (통계청 2024, source-index #14)
- **AI 생성(해석·요약·재구성)**은 인용이 아님을 분명히 한다. 해석은 근거 위에서만.
  - 예: 위 통계를 근거로 본 사업의 SAM을 추정하면… ([추정], ledger L5)
- **인용과 해석을 한 문장에 섞지 않는다.** 인용 문장 / 해석 문장을 분리하면 평가자가 "어디까지가 사실인지" 즉시 구분한다.
- 파일 다운로드·분석 실패는 숨기지 않고 명시한다(미분석 특허·논문 포함, PRD §26).

## 6. "출처 없는 핵심 통계 0건" 검증

이 한 줄이 통과 기준(Gate 7)이자 비기능 요구사항(PRD §26)의 핵심이다.

### 자동 검증
- `scripts/validate_project.py bizplan-<slug>/` — `08-draft/` 본문에서 수치 패턴을 스캔해 태그·행참조가 없는 수치를 보고(기계 점검). 숫자 일관성(섹션 간 동일 수치)도 함께.
- 보조 grep: 본문에서 `%`, `억`, `조`, `만원`, 배수(`배`, `x`) 등 핵심 수치 토큰을 뽑아 각각에 태그가 붙었는지 대조.

### 수동 검증 (평가위원 시뮬에서)
- **사업성 평가자**: 모든 시장·재무 수치가 `evidence-ledger`/`source-index`로 추적되는가?
- **회의적 반대 평가자**: 가장 유리한 수치 3개를 골라 출처를 역추적 — 자사에 유리한 자료만 골랐거나 출처가 약하면 결함으로 기록.

### 판정 규칙
- "핵심 통계" = 평가 점수·의사결정에 영향을 주는 수치(시장 규모, 매출, 성능, 점유율 등). 본문 장식 수치가 아니라 근거가 되는 수치.
- 핵심 통계 중 `source-index`/`evidence-ledger` 행이 없는 것이 **1건이라도** 있으면 Gate 7 미통과.
- 출처를 찾지 못하면 그 수치를 `[확인 필요]`로 강등하고 핵심 근거에서 제외한다(삭제가 아니라 강등).

## 7. 단계별 태깅 적용 요약

| 단계 | 태깅 행동 |
|---|---|
| 인터뷰 | 답변을 `confirmed-facts.md`([사실])·`assumptions.md`([가정])·`follow-up-items.md`([확인 필요])로 분류 |
| 리서치 | 수집 즉시 `source-index.xlsx` 등재, 주장은 ledger 행으로 |
| 코어 | `business-core.yaml` 모든 값에 태그 + 행참조 |
| 초안 | 본문 수치에 태그 노출, 시각자료에 기준일·출처 |
| 검증 | "출처 없는 핵심 통계 0건" 자동+수동 확인 |

> 마인드셋: "이 수치의 출처는 source-index 몇 번 행인가?" / "이건 [사실]인가 [목표]인가?" — 두 질문에 즉답할 수 없는 수치는 아직 문서에 들어갈 자격이 없다.
