3레코드 스키마

모든 레코드는 동일한 8개 필드로 정규화된다 — 같은 모양이라야 dedupe·정렬·집계가 가능하다.

수집된 게시물은 출력 전에 JSON 레코드로 정규화한다. 각 레코드는 카테고리, 작성자, 핸들, 날짜, 요약, URL, 조회수, 좋아요의 8개 필드를 가지며, 요약은 한국어 1~2문장으로 사실 위주·출처 결속이다. 아래는 단일 레코드의 표준 구조다.

{
  "cat": "신규 모델·제품 출시",
  "author": "Anthropic",
  "handle": "@AnthropicAI",
  "date": "2026-06-05",
  "summary": "에이전트 도구 호출을 표준화하는 신규 SDK를 공개. MCP 호환 명시.",
  "url": "https://x.com/AnthropicAI/status/1930000000000000001",
  "views": 412000,
  "likes": 5800
}

url은 레코드를 식별하는 유일 키다. 같은 게시물을 다시 수집하면 새 행을 추가하지 않고 기존 행을 최신 값으로 갱신한다. URL은 쿼리스트링·트래킹 파라미터를 제거한 정규화 형태로 비교한다.

4수집 요약 · append/update

신규 수집을 기존 데이터셋에 병합한 결과를 incoming/existing/added_net/total로 닫는다.

이번 실행은 기존 데이터셋(11건)에 이번 창 수집분(20건 시도)을 병합한 결과다. URL 기준 dedupe·update를 거쳐 순증 7건, 기존 4건 갱신으로 총 18건이 되었다.

existing

병합 전 기존 레코드 11건

incoming

이번 창 수집 시도 20건

added_net

중복 제거 후 순증 +7건

updated

기존 URL 값 갱신 4건

duplicates

동일 URL 재수집 13건(병합)

total

병합 후 데이터셋 18건

병합 파이프라인 순서

수집 → 정규화 → dedupe/update → 집계 → 정적 렌더의 단방향 흐름입니다.

append/update
  1. 수집 — 읽기 전용으로 게시물 열람, 8필드 후보 추출(20건 시도).
  2. 정규화 — 카테고리 매핑, 요약 1~2문장, URL 정규화, 미확인 지표 0/unknown.
  3. dedupe/update — URL 키로 기존 11건과 대조, 중복 13건은 갱신, 신규 7건 추가.
  4. 집계 — 카테고리 분포·상위 신호 계산(확인된 지표만 사용).
  5. 정적 렌더 — 사전 분류·사전 정렬된 섹션으로 무 JS 출력.

없는 숫자는 만들지 않는다 — 미확인·숨김·반올림 지표를 표기 규칙으로 고정한다.

X의 노출·좋아요는 경로에 따라 가려지거나 반올림되어 표시된다. 이 대시보드는 그 한계를 숨기지 않고 표기 규칙으로 드러낸다. 지표를 확인할 수 없으면 0 또는 unknown으로 두며, 어떤 경우에도 추정값을 만들어 넣지 않는다.

"비슷한 게시물이 보통 1만 정도니까 1만으로 둔다" 같은 보간은 금지된다. 추정 한 번이 전체 상위 신호 순위를 왜곡하고, 이후 갱신에서 진짜 값과 충돌한다. 미확인은 끝까지 0/unknown으로 남기고, 순위 계산에서 명시적으로 제외한다.

이번 데이터셋에서 지표 미확인 레코드는 5건이며, 모두 0으로 표기하고 §6 상위 신호 순위에서 제외했다.

8중복/추가 정책

같은 게시물을 다시 만나면 행을 늘리지 않고 갱신한다 — URL 기준 dedupe/append 규칙을 못 박는다.

수집은 반복 실행되므로 같은 URL이 여러 번 들어온다. 정책은 단순하다. URL이 같으면 같은 레코드다. 새 행을 추가하는 대신 기존 행의 지표·요약을 최신 값으로 덮어쓴다.
