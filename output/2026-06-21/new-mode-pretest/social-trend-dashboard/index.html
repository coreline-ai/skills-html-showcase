8dedupe_append_policy · URL dedupe와 append 규칙

같은 URL·같은 주장의 중복을 줄이되, 시간차로 바뀐 내용을 잃지 않기 위한 정책 느낌을 구체화합니다.

URL dedupe flow
1. normalize

scheme, host, trailing slash, tracking query, fragment를 정리해 canonical_url을 만듭니다.

2. compare

canonical URL과 title fingerprint를 비교해 동일 페이지·동일 주장 후보를 찾습니다.

3. append

날짜나 가격처럼 변동 가능 필드가 다르면 기존 레코드에 observation을 append합니다.

동일 URL + 동일 주장

기존 레코드의 observations[]에 수집 시점만 추가하고 top signal count는 1로 유지합니다.

동일 URL + 변경된 주장

가격·기능·제한처럼 의미가 바뀐 경우 새 observation으로 append하고 caveat를 갱신합니다.

서로 다른 URL + 같은 주장

증거 카드에는 대표 1개만 노출하되, backing sources count를 별도 표기합니다.
